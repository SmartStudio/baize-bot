# 白泽个人助理规格 v0.2

日期 2026-09-25，基线主干 `4434acc`。v0.1 是按「公司内部三个人用的多 Bot 协作工具」写的，本版改成「一个人的助理带一支 Bot 小队」。v0.1 在 git 历史里，两版的差别在附录 A。

本文写目标形状。每个对象后面的「现在」一行写代码里已经有的样子，开发的人按两者的差距排活，分期在 `plan/开发计划.md`。用户会怎么用它写在 `spec/用户故事.md`，本文用 U 编号引用那里的故事。界面以 `spec/原型/个人助理-v4.html` 为准。

## 一、定位

白泽是一个人的助理。你只跟主助理说话，它带一支 Bot 小队替你干活，内容、社区、增长各有专人。活跑在你自己的电脑上，碰你开给它的账号。它只在三种时候找你，要你拍板、做完有成果、卡住了。

第一阶段只服务一个人，只做运营一条线。验收是「用白泽推广白泽的开源仓库一周」，你既是第一个用户，也是第一个运营对象。娱乐排在运营之后，德州先于剧本杀。企业版的管理台、多租户、团队结算都不做。

确认模型是这个产品的核心。所有动作过一道闸，对外发布的东西以可编辑草稿给你看，批一份内容计划，按计划发出的每一条不再逐条问。

## 二、对象模型

### 用户

一个账号对应一个人，字段有姓名、邮箱、密码。注册即可用，没有企业域名和管理员开通。用户是所有确认的唯一审批人。

现在。只能靠 `seed` 建账号，没有注册接口。`users.team_name` 和登录页的企业文案是 v0.1 的遗留。

### 电脑

Bot 干活的地方，每人两台，本机和远程。

- **本机。** 你的 Mac，装 App 时一起装上电脑代理。国内平台的账号放这里，走你家里的网络出口，封号风险低。合盖就离线。
- **远程。** 你自己的一台云服务器，跑电脑代理、Xvfb 和 Chrome。GitHub、X、资料搜集放这里，你合盖了照样跑。控制面也放在这台机器上。服务器放海外，因为放在上面的 GitHub 和 X 在国内访问不稳。

`computers` 按 `(owner_id, kind)` 各一行，`kind` 是 `local | remote`。字段还有状态（未连接、在线、离线、故障）和最后在线时间。两台都是电脑代理出站连控制面，协议一样。

现在。`computers.owner_id` 带唯一约束，一人一台。连接表、收尾链、派活都按 owner 算，`runs` 没有 `computer_id`。

### 账号

你开给它的一个平台账号，住在某一台电脑的助理专用浏览器里。字段有平台、账号名、所在电脑、登录状态（有效、过期）、权限档。

权限档有四个，只读、可起草、发布要确认、可直接发布，默认「发布要确认」。碰这个账号的活只能派到它所在的那台电脑。有 API 的平台（GitHub、X、邮箱）走 OAuth，凭据由工具在调用时注入，模型只看到结果。

现在。没有这个对象。只有 MCP 工具连接上一个手填的 Bearer 头，`SiteLogin` 类型定义了但没人用。

### Bot

属于一个用户，字段有名称、标签（`tags: string[]`，有数量上限）、一句话描述、头像色、偏好、会做的事（skill）。名称以外都不必填。Bot 分四种角色。

| 角色 | 谁定 | 进团队页 | 留记忆 |
| --- | --- | --- | --- |
| 主助理 | 注册时建好，唯一 | 是 | 是 |
| 队员（内容、社区、增长、排版） | 主助理提议，你确认 | 是 | 是 |
| 临时帮手（资料员、翻译） | 主助理随拉随散 | 否 | 否 |
| 牌友和解说 | 你直接挑、直接换 | 只在游戏项目里 | 是 |

权限挂在账号和项目上，不挂在 Bot 上。多一个 Bot 不多一份权限。

现在。Bot 有名称、单个 `tag` 字符串、描述、可用工具、skill。没有角色。现有的「首席」是群属性，主助理由它演化来。

### 项目

你想做成的一件事，比如「白泽开源首发」「小红书起号」「周末德州」。一个项目就是一个群加一张主题任务卡，卡上加目标（数值、单位、截止）和指标（定时读回的数，比如星数、粉丝数）。项目有队伍、计划、例行和成果。

不属于任何项目的事归「日常」，比如每天晚上的简报。你和某个 Bot 的单聊是只有它一个成员的群，留着，不是主入口。

现在。群、单 Bot 群、多 Bot 群、主题任务卡和清单都完整，有测试。卡上没有目标和指标，界面上叫「主题任务」，带 `T-xxxx` 编号。

### 消息

群里的一条记录，是事实来源。类型沿用现在的用户消息、Bot 消息、系统消息、工具调用、审批、交接、skill 提议、花费。加一个可见范围 `visibleTo`，空表示全群可见，游戏里的底牌和线索靠它。

派活拼上下文时按收件 Bot 过滤可见范围。

现在。没有 `visibleTo`，其余完整。

### 草稿与内容计划

Bot 要对外发的东西先成草稿。草稿字段有平台、账号、所在电脑、正文、配图、计划发出时间、内容哈希、状态（待批、已批、已发、退回）。内容计划是一组草稿，可以一次批完。

批准记下每条草稿的内容哈希。到点发出时哈希对得上就放行，对不上就回到待批。批内容，不批点击，这样运营的活才能在你不在的时候跑。

现在。没有。

### 确认与授权

所有工具调用先过一个统一的判定函数，挂在 Pi 的 `tool_call` 上，包括 bash、write、edit、浏览器和 MCP。

```ts
type ActionKind =
  | "read"             // 读网页、读文件、查数据
  | "write_workspace"  // 在它自己的工作目录里写
  | "write_outside"    // 工作目录以外的文件
  | "delete"
  | "shell"
  | "publish"          // 公开发帖、发评论、发 PR
  | "message_person"   // 私信、邮件、加好友
  | "engage"           // 点赞、关注、收藏
  | "spend"
  | "account_security" // 改密码、改绑定、授权第三方
  | "install";

type Verdict = "allow" | "ask" | "deny";

type Grant = {
  action: ActionKind;
  target: AccountId | Domain | PathPrefix;
  scope: "once" | "project" | "until" | "forever";
  expiresAt?: Date;
  projectId?: ProjectId;
};
```

判定按四层走，前一层有结论就不看后面。

1. 禁区。`~/.ssh`、钥匙串、浏览器的登录资料（包括助理专用 Chrome profile 的 cookie 文件）一律拒绝，读写都不行，你给了授权也不行。禁区是路径前缀的一张固定表，不是按文件名猜。
2. 硬清单。`spend`、`account_security`、删除你的文件、授权第三方应用，永远问，不接受 `forever`。
3. 你给过的 `Grant`，以及账号的权限档。
4. 默认表。

| 动作 | 工作目录里 | 工作目录外 |
| --- | --- | --- |
| 读 | 放行 | 问。你给过这个目录的授权就放行，比如在某个项目里允许读 `~/Downloads` |
| 写 | 放行 | 问，没有 `forever` |
| 删 | 放行 | 问，没有 `forever` |
| 读网页、查数据 | 放行 | 放行 |
| 其余动作 | 问 | 问 |

工作目录是 `<dataDir>/<botId>/` 下这个 Bot 自己的目录。

bash 命令先解析出动作类别再判，解析不出的当 `shell` 问。运行器放弃一条确认时发上行报文，控制面把那一行改成「已失效」，不能再点。

现在。`approvalRule` 只看 MCP 操作上的 `needsApproval`，Pi 内置的 bash、write、edit 完全不过审批，`read` 接受绝对路径和 `~`，Bot 能读到 `~/.ssh`。运行器放弃的审批控制面仍显示待批。审批卡的摘要是 `JSON.stringify(event.input)`。

### 例行

到点替你做的一件事。字段有名称、做什么、触发器（定时、webhook）、所属项目（可空，空即日常）、执行者（主助理可换的 Bot）、边界（只读、草稿等你批）、状态、上不上首页、运行记录。

状态是 `on | paused | auto_paused`。一条例行的结果连续三次没人看，它自己停，和你手动暂停分开显示。项目归档时它的例行一起停。

现在。例行挂在 `botId` 上，`enabled` 是布尔。定时和 webhook、调度游标、运行记录都完整。电脑不在线记失败。

### skill 和偏好

skill 是 Bot 会做的一件事，沿用现在的机制。Bot 干完多步的活提议存，你点存才存，随 config 下发成 `SKILL.md`。来源加一个 `template`，表示随模板导入。

偏好是你在单聊里教 Bot 的一句话，比如「标题别超过 15 个字」。字段有正文、来源消息、是否私人。偏好当场可见、可删，写作时套用。

品牌手册是所有 Bot 共用的一份资料，写产品事实、口吻、禁区和你的素材。你改过的草稿，改了什么记进这里。

现在。skill 完整。偏好和品牌手册没有。

### 模板

分享出去的 Bot 配方。一定带名字、标签、描述。默认带、可取消的是 skill 和你提炼的插件（带配置，不带登录）。偏好逐条勾，标了私人的默认不勾。永远不带账号登录、对话记录、文件、项目。

导入即复制，得到一个独立的新 Bot，原作者以后再改不同步。第一版没有版本号，没有公开模板库。

现在。没有。

### 用量

每次 run 结束记一条，字段有 Bot、项目、时间、步数、模型用量、折算金额。设置里按月、按 Bot 汇总，有月预算，超预算先停例行。

现在。有用量表和按 Bot 汇总。`run_done` 报的是 Pi 会话的累计 token，每群一份会话续用之后会重复计算，这是正确性问题。

## 三、核心流程

### 注册和第一次打开

对应 U1。用户注册后进「今天」页。App 调「注册本机」接口拿电脑 token，存进钥匙串，经 stdin 交给电脑代理，不走环境变量。主助理在注册时建好。远程电脑可以之后在设置里加。

### 建项目

对应 U2、U8。你说一句想做成什么事，主助理回一张方案卡，写项目名、目标、队伍、要用的账号、节奏、第一步。点「开始」才建，和 `skill_offer` 一样先提后存。建项目时不逼你连账号，等第一条要发的内容写好再请你登录。没有表单式的新建。

### 派活

你在首页说的话进主助理的单聊，在项目页说的话直接落进那个项目的群。主助理决定这句话谁接，队员之间用现在的 @、交接和首席机制接力，这些在界面上收成过程里的一行。

路由、群回合、回路上限沿用 `control-plane/src/agent/routing.ts` 和 `group-turn.ts`，设计理由在 `packages/control-plane/README.md`。项目群里主助理就是首席。

### 过闸

Bot 调任何工具都先过第二节的判定。`allow` 直接执行。`ask` 在「等你确认」里出一张卡，工具调用挂起等结果，你批了从断点继续。`deny` 让工具抛一个中文错误，Bot 看到原因换路子。暂停和接管也走这道闸，挂起而不是 `abort()`。

### 草稿和内容计划

Bot 调 `publish` 类工具时不直接问「允许吗」，而是生成草稿。卡片上显示平台、账号、正文和配图，你直接改字再批。一份计划的 N 条一次批完。你改过的地方记进品牌手册。

### 开账号和登录接管

对应 U3、U7。每台电脑一个助理专用的 Chrome profile，Bot 通过 CDP 在后台窗口操作，不抢你的鼠标键盘。要登录时它把那个窗口弹到前台，你扫码或输密码，验证码和二次验证也由你来。登录完窗口退回后台。登录过期时只停碰这个账号的活。

浏览器工具写在运行器里，参照 Pi 官方 `pi-skills/browser-tools` 的裸 CDP 做法，不走 MCP。

### 例行

对应 U10。在对话里说一句，主助理回一张确认卡，写清时间、项目、执行者、边界，点「加上」才生效。改例行也回对话，输入框预填一句话。调度器沿用现在的，派到执行者该去的那台电脑，远程电脑在线就不怕合盖。

### 分享与导入

对应 U14。分享弹窗默认一段话说清带什么、不带什么，底下「复制链接」。导入得到新 Bot，接导入者自己的账号。插件导出成不含凭据的配置。

### 牌局

对应 U15。发牌、底池、行动合法性、结算全部在控制面的确定性引擎里，模型只负责决策和台词。牌力和位置由代码算好再给模型，模型裸打很弱。你的手牌只有你和引擎看得见。无真钱，无筹码兑换。

剧本杀排在德州之后，用现成剧本，主持只拿当前阶段能公开的内容，真相放在引擎里。

## 四、界面规矩

### 露什么

一条信息露不露出来，只看它会不会改变你下一步的动作。

- **明面上。** 草稿正文，发到哪个平台哪个号，什么时候发，发出后的链接和数据，项目离目标还差多少。
- **收起来。** 做了哪些步骤、哪个 Bot 做的、用了什么工具，收成一行「做了 N 步」，展开是人话步骤，再往下是右侧检查器。runId、模型名、原始参数只在检查器的「高级」里。
- **删掉。** 任务编号、系统小字、每轮花费（改成设置里按月汇总）、「消息来自」、审批卡里的原始 JSON。

### 首页「今天」

用原型里的方案 A「今天清单」。另外两种排法不做，对话优先会让新消息把确认卡冲走，项目看板要多点一下才看到草稿。看板的指标一览放进项目页。

顶上一句问候和输入框。左栏「等你确认」和「刚做完」，右栏「在进行」和「接下来」。「在进行」每个项目一行，带进度条。「接下来」只列已排期的发布和标了上首页的例行。

### 项目页

从上到下六块。对应 U9。

1. 项目名、目标、进度条和本周变化。
2. 项目自己的输入框。
3. 最近一轮对话紧贴在输入框下面，更早的折成「更早 N 轮」。
4. 等你。只放这个项目的卡，正在做的事以一行灰字出现，写好变成卡。
5. 本周计划、下一步、成果。成果按时间倒序，数据来自发布记录和计划状态，不是历史消息。
6. 折起来的「队伍 N · 例行 N」。

消息在这一页只是指令，结果落进固定块。

### Bot 页

在团队页点一张 Bot 卡片，进去就是和它单聊。顶上名字、一句话描述，右边「编辑」和「分享」。下面一行「它知道的 · 记住 N 条 · 会 N 件事 · 在 N 个项目」，点开才列出来。技能来源、插件勾选、模型不在这里露出。

### 设置

左下角齿轮，一个弹窗五页。Bot 的事去 Bot 页，你的事去设置。

| 页 | 放什么 |
| --- | --- |
| 通用 | 三种通知开关、夜里免打扰、菜单栏常驻、开机启动、外观、语言、时区 |
| 账号与电脑 | 按电脑分组列账号，每个号只显示当前那一档，点开才换。页尾加电脑、本机能碰的文件夹、永远要问的四件事 |
| 插件 | 内置的和你提炼的分开标，写清谁在用 |
| 用量 | 本月花费和预算，按 Bot 分 |
| 数据与隐私 | 导出全部数据，记忆存在哪，删账号 |

### 通知和菜单栏

通知只在三种时刻发，要你确认、做完有成果、卡住了。夜里免打扰时攒着。菜单栏常驻，数字只数等你确认的事，点开能直接批，也能说一句。

## 五、运行架构

```
桌面 App（Electron，界面和 Web 同一份）
  │ HTTP /api，WebSocket /api/ws
  ▼
控制面（Hono + Postgres，放在你的远程服务器上）
  │ WebSocket /agent，config 下发
  ▼
电脑代理 ×2（本机、远程）
  └─ Bot 运行器：每个 Bot 每个群一份 Pi 会话，统一闸门，浏览器工具
       │ 模型请求走控制面 /gateway/v1
       ▼
     模型上游（多模型：闸门分类用便宜的，规划用强的，截图能进）
```

沿用 v0.1 的部分。控制面、电脑代理、Pi 运行器这条链路，出站连接，模型网关换 key 换模型，群消息是事实来源，会话文件是 Pi 的 JSONL 落在 `<dataDir>/<botId>/` 下，`~/.pi` 不出现新文件。

改了的部分。

- 控制面从「我们的云」改成你自己的远程服务器，以后对外再换托管部署。
- 过夜机改成你自己的远程电脑，一台机器只有你一个人，不再按用户分进程。
- Bot 不再用你屏幕上的浏览器，改用每台电脑一个助理专用 Chrome profile。
- config 从整份换运行器改成按 Bot 增量对账，只重建改了的那个 Bot 的会话，没在跑的才重建。
- 网关从一个上游一个模型改成多模型，收图片。

## 六、第一阶段范围

第一阶段是开发计划的第 0 到 2 期。

做的：注册、本机和远程两台电脑、Electron 壳和菜单栏、统一闸门和授权、草稿和内容计划、助理专用浏览器和账号、「今天」首页、项目（目标、指标、计划、成果）、主助理带队和建队卡、单聊和偏好、品牌手册、例行挂项目、模板分享、多模型网关、按月用量和预算。

不做的：管理台、多租户、计费、公开模板库、模板版本、手机、剧本杀、Bot 接管你屏幕上的浏览器、VNC 画面流、SSO。德州在第 3 期。

## 七、已定和待定

2026-09-25 定下的：

1. **第一批平台是 GitHub、X、小红书。** GitHub 有 API，X 是海外社交，小红书是国内社交。小红书没有公开的发帖接口，只能走助理浏览器，账号放本机。GitHub 和 X 走 OAuth，账号放远程。
2. **远程服务器放海外。** 跟着第一批平台定。
3. **bash 的边界。** 按第二节「确认与授权」的四层判定。工作目录里放行，工作目录外的读要授权或问，写和删一律问，禁区一律拒绝。`archive/n7-scope`（标签） 的黑名单做法不用，那个原型里 `~/.ssh` 照样能读。
4. **首页用方案 A「今天清单」。** 见第四节。

还待定的：

1. **游戏的优先级。** 默认排在运营之后。第 3 期和第 2 期碰的代码不重叠，要并行可以。
2. **品牌。** 设计系统 readme 写「暖纸色、橘色品牌色」，token 实际是冷灰加蓝。个人版换不换主色，要不要一个字标。
3. **人设文案。** 系统提示里主助理和队员的人设那一句归你定稿。
4. **模型供应商和计价表。**

这四项都不挡第 1 期开工，没定之前按默认做。

## 附录 A. 和 v0.1 的差别

| v0.1 | v0.2 | 原因 |
| --- | --- | --- |
| 公司内部三个人用 | 一个人用 | 先把自己服务好，企业版没对外发过 |
| 侧栏是 Bot 和群 | 首页是「今天」 | 你要的是要处理的事，不是会话列表 |
| 主题任务，`T-xxxx` 编号 | 项目，带目标和指标 | 运营的事按目标衡量 |
| 你 @ 具体的 Bot 派活 | 你只跟主助理说，谁接由它定 | 普通用户不该排班 |
| 只有 MCP 工具上标了的操作要点头 | 所有动作过一道闸，带范围授权 | 开账号给它之后，bash 和浏览器才是大头 |
| 审批是「允许吗」 | 对外发布是可编辑草稿，批计划不批点击 | 逐条问会让你开始无脑点批准 |
| Bot 用你屏幕上的浏览器，接管就是它松手 | 助理专用浏览器，后台窗口，你只管登录 | 不抢屏幕，说得清开了哪些账号 |
| 公司一台共用过夜机 | 你自己的远程电脑 | 个人版没有公司 |
| 例行挂在 Bot 上 | 例行挂在项目上 | 你想的是项目每周五复盘，不是某个 Bot |
| Bot 设置常驻右侧栏 | Bot 页，资料进「编辑」弹窗 | 设置比对话还抢眼 |
| 设置有工具、电脑、用量等 | 五页，账号和电脑并一页 | 账号本来就绑在电脑上 |
| 没有分享 | 分享配方，导入即复制 | 同步会让对方的 Bot 在对方不知道时变样 |
