# 白泽 Bot 规格 v0.1

日期 2026-09-18。依据是 research/grok-bot-对照研究.md 第 11 节的十二项决定和 bot-application-prototype/白泽 Bot.dc.html 的 12 张屏。本文只描述第一版要做的东西。每个对象和流程后面标注对应的原型屏编号。待定项集中在第五部分。

## 一、对象模型

### 用户

一个账号对应一个人。字段有姓名、邮箱、密码或 SSO 身份、所属团队名（只做展示）。一个用户拥有一台云电脑和任意多个 Bot。用户是所有审批的唯一审批人。

### 云电脑

每个用户一台，Firecracker microVM，Debian 系 Linux。字段有状态（创建中、在线、休眠、故障）、宿主机、闲置计时、已登录站点列表。同一用户的所有 Bot 共用这台电脑的文件系统、命令行和浏览器登录态。闲置 7 天休眠，文件保留。云电脑可以跑在我们的宿主机池，也可以跑在客户内网的宿主机上。控制面永远不主动连电脑，电脑里的代理出站连到控制面。对应 07 设置的电脑页。

### 桌面

每个 Bot 一个，属于该用户的云电脑。桌面是一个独立的图形会话，Bot 在里面开浏览器和应用。字段有所属 Bot、状态（空着、干活中、被接管）、当前画面流地址。桌面不是安全边界，只用来让多个 Bot 并行。对应 02 主窗口的桌面面板和 11 桌面切换。

### Bot

属于一个用户。字段有名称、标签、描述、头像色、通知开关、可用工具（从用户已连接的 MCP 里勾选的子集）、会做的活（skill 列表）、例行任务列表。描述是 Bot 的边界，用户把「什么先找我点头」写在这里。没有岗位模板。删除 Bot 不删电脑里的文件和登录态。对应 2b 新建 Bot 和 2a 的 Bot 设置。

### 群

群是对话的唯一容器。一个群绑定一个主题任务，成员是归属人加 1 到 6 个 Bot。一对一对话是只有一个 Bot 的群，建 Bot 时系统自动建这个群。群里的消息按时间排一条线，Bot 用 @ 指派。对应 08 建群和 2a 对话。

### 主题任务

一个群有且只有一个。字段有编号（T 加四位数字，系统分配）、标题、一句话说明、截止（可选）、清单、当前经手 Bot、经手记录、状态（进行中、完成）。清单是若干条目，每条有文字和完成状态，由 Bot 通过工具维护，用户也能在群里改。单 Bot 的群也有主题任务，标题默认是 Bot 名，不显示任务卡。对应 08 建群和 05 的任务卡。

### 消息

群里的一条记录。类型有用户消息、Bot 消息、系统消息、工具调用、审批、交接报文、花费卡。Bot 消息可以流式更新。工具调用消息展示工具名、参数摘要、耗时、状态。其他 Bot 在群里说话时标注「消息来自 小销 · 销售」。对应 2a 和 02 的对话区。

### 审批

一条特殊消息，由 Bot 在执行到点头清单里的动作时发出。字段有动作类别（对外发送、改生产数据、付钱）、动作摘要、状态（等你点头、已批准、已拒绝）、处理时间。归属人在群里回复或点按钮完成审批。审批只针对这一次动作，不针对已完成的工作。超时不升级，只提醒。侧栏角标「等你点头 N」统计未处理的审批数。对应 02 和 2c 的审批卡。

### 交接报文

一条特殊消息，从一个 Bot 发给同群另一个 Bot。字段有做了什么、没做什么、下一步、清单指针、状态（等 Bot 确认、已接手）。接手后主题任务的当前经手 Bot 变更，经手记录追加一条。Bot 之间的确认不等于用户的审批。超时只提醒用户，不退回，不升级。对应 05 Bot 间交接。

### 工具连接

用户级对象。一个工具连接是一个 MCP 服务的地址和认证信息，加上分配给哪些 Bot。Bot 只能用分配给它的工具。工具的每个操作带一个「需要点头」标记，默认按 MCP 的注解决定，用户可改。对应 07 设置的工具页。

### 已登录站点

云电脑浏览器里的登录态，按站点域名列出。字段有域名、登录时间、谁登录的、状态（有效、过期）。属于电脑，所有 Bot 共用。过期时 Bot 停下，请用户接管桌面登录。对应 07 工具页下半部分。

### Skill

属于一个 Bot。字段有名称、来源（对话存的、例行任务存的、你教的）、步骤列表、使用次数。Bot 干完一件活后问用户存不存。用户可改步骤、删除、复制给别的 Bot。在对话里用 / 引用。对应 10 skill。

### 例行任务

属于一个 Bot。字段有名称、每次运行做什么、触发器列表、失败时（停下告诉我、下次再试）、启用开关、运行记录（最近 20 条）。触发器第一版只有定时和 webhook。运行结果以消息回到该 Bot 的群里。对应 2c 例行任务。

### 用量记录

每次 Bot 运行结束记一条。字段有 Bot、群、开始和结束时间、步数、模型用量、折算金额。按 Bot 汇总显示在设置的用量页。周预算和团队结算是后续。对应 02 的花费卡和 07 的用量页。

## 二、核心流程

### 登录

用户输入企业域名，系统判断走 SSO 还是账号密码。第一版先做账号密码，SSO 接标准 OIDC。登录后进主窗口，侧栏列出该用户的 Bot。首次登录时后台创建云电脑。对应 01。

### 建 Bot

点侧栏的加号。系统立即创建 Bot、它的单 Bot 群、它的桌面。右侧设置栏可以补名称、标签、描述。用户可以直接在下方派第一个活。对应 2b。

### 派活

用户在群里发消息。控制面把消息送到该 Bot 的运行时会话。Bot 回复流式写回群。Bot 需要工具时，工具调用作为消息出现在群里。运行结束时群里出现花费卡。对应 2a 和 02。

### 建群与主题任务

用户点加号选「建群」，填主题任务标题、拉 2 到 6 个 Bot、写一句话说明、可选截止。系统分配编号，任务卡钉在群顶部。用户 @ 一个 Bot 派活，该 Bot 成为当前经手。对应 08。

### 群里的多 Bot 会话

每个 Bot 有自己的运行时会话。群消息只送给被 @ 的 Bot 和当前经手 Bot。Bot 看到的上下文是群里最近的消息和主题任务卡。Bot 用工具更新清单、发交接报文、@ 别的 Bot。对应 05。

### 审批

Bot 的运行时在执行工具调用前检查该操作是否需要点头。需要时运行时暂停，控制面在群里发一条审批消息并推通知。用户点按钮或回复。运行时收到结果后继续或放弃这个动作。用户免打扰期间审批攒着，Bot 照常做不需要点头的部分。对应 02。

### 交接

当前经手 Bot 发交接报文给同群另一个 Bot。目标 Bot 的运行时收到报文，回复确认后成为当前经手。用户在任务页看到经手记录。超时提醒用户。对应 05。

### 接管与交回

用户在桌面面板点接管。该 Bot 的运行时暂停，桌面画面流转为可输入。用户操作完点交回，运行时从断点继续。登录态过期是最常见的接管原因。对应 02 和 11。

### 工具连接

用户在设置的工具页填 MCP 地址和认证信息，勾给哪些 Bot 用。控制面保存配置，电脑里的运行时按 Bot 加载工具列表。Bot 设置里的可用工具行打开同一页。对应 07 工具页和 09。

### 例行任务

用户在 Bot 设置的例行页新建。控制面的调度器按触发器发起一次运行，等同于用户在该 Bot 的群里发了一条消息。失败时按设置停下或下次再试。对应 2c。

### skill

Bot 干完一件多步骤的活后问用户存不存。用户点存，运行时把步骤写成 skill 文件并同步到控制面。用户在 Bot 设置的会做的活里查看和修改。对应 10。

## 三、运行架构

### 三块

- 控制面。SaaS，一套服务。管账号、Bot、群、消息、任务、审批、工具配置、调度、用量。对外提供 HTTP API 和 WebSocket。
- 客户端。第一版是 Web 应用，样式沿用原型的设计系统。桌面壳是后续。
- 云电脑。每用户一台 Firecracker microVM。里面跑两个进程，电脑代理和 Bot 运行器。

### Bot 运行器用 Pi

Bot 运行器是一个 Node 进程，用 pi-coding-agent 的 SDK 嵌入，每个 Bot 一个 AgentSession，全部跑在这台云电脑里。选在电脑里跑而不是在控制面跑，原因是 MCP 服务和业务系统可能只在客户内网可达，工具流量不能出内网。

运行器通过 Pi 的扩展机制注册这些工具：桌面操作（截图、点击、输入，绑定到该 Bot 的桌面）、MCP 桥接（按 Bot 的分配加载）、主题任务（更新清单、发交接、@ 别的 Bot）、存 skill。Pi 自带的读写文件和命令行工具保留。

审批用 Pi 的 tool_call 事件拦截。扩展在事件里判断操作是否需要点头，需要时向控制面发审批请求并等待，得到拒绝就返回 block。

模型调用不直连供应商。运行器把控制面的模型网关注册为 OpenAI 兼容的自定义供应商。网关负责选模型、记用量、换供应商。云电脑只需要能出站到控制面。

会话文件是 Pi 的 JSONL，存在电脑里该 Bot 的目录下。群消息是产品的事实来源，存在控制面数据库。运行器把群消息作为提示送进会话，把会话产出的文本和工具事件写回群。

### 电脑代理

一个常驻进程，启动时出站连到控制面并保持 WebSocket。它负责收发运行器的指令、转发桌面画面流、报告电脑状态、同步 skill 文件和成果文件、列出浏览器已登录站点。控制面通过这条连接下发工具配置和消息。

### 桌面

每个 Bot 一个独立的图形会话，每个会话一个浏览器。画面用 VNC 协议经电脑代理转发到客户端。接管就是客户端在同一条通道上发送输入。浏览器登录态共享的具体机制是待定项，见第五部分。

### 数据

控制面用 PostgreSQL 存第一部分的全部对象。文件和截图存对象存储。消息推送用 WebSocket。调度器是控制面内的定时任务，第一版单实例。

### 部署

控制面部署在我们的云上。宿主机池是若干台支持 KVM 的机器，每台跑若干 microVM。客户内网部署时，客户提供宿主机，宿主机上的电脑代理出站连到控制面。控制面不需要访问客户内网。

## 四、第一版范围

对内给白泽明理的 AI Operation 用。跑通的定义是一个群里的多个 Bot 通过持续对话跟踪一个主题任务，中间经过审批、交接和接管。

做的：账号密码登录、建 Bot、单 Bot 群、多 Bot 群、主题任务和清单、审批、交接、桌面面板和接管、MCP 工具连接、已登录站点、skill 的存和改、例行任务的定时和 webhook 触发、按 Bot 的用量。

不做的：管理台、多租户、计费、周预算、团队模板、移动端、桌面壳和本地文件访问、邮件和 IM 触发器、教 Bot 录屏、SSO 以外的第三方身份。

## 五、待定项

1. Pi 指 badlogic/pi-mono。本文按它写。需要确认。
2. 客户端形态。本文选 Web 应用。原型里「这台 Mac」页的本地文件和本机上网两项依赖桌面壳，第一版不做。需要确认。
3. 浏览器登录态在多个桌面间怎么共享。备选是每个桌面一个浏览器加登录态同步，或一个浏览器多个窗口分到不同桌面。开发计划的 M1 用实验定。
4. 模型供应商首选和模型网关的计价表。
5. 通知渠道。Web 版只有浏览器通知和侧栏角标。
6. 宿主机规格和一台宿主机跑几台电脑。M1 实测后定。
7. 时间和人手。见开发计划。
