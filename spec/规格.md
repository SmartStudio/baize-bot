## 一、定位

白泽是一个人的助理。你只跟主助理说话，它带一支 Bot 小队替你干活，内容、社区、增长各有专人。活跑在你自己的电脑上，碰你开给它的账号。它只在三种时候找你，要你拍板、做完有成果、卡住了。

第一阶段只服务一个人，只做运营一条线。验收是「用白泽推广白泽的开源仓库一周」，你既是第一个用户，也是第一个运营对象。娱乐排在运营之后，德州先于剧本杀。企业版的管理台、多租户、团队结算都不做。

白泽的核心能力是接进你在用的系统。国内是飞书、企业微信、钉钉，海外是 WhatsApp，这些是你和 Bot 说话的地方。CRM、ERP 是 Bot 干活时读写的地方。你不必为了用白泽换工具，白泽进到你已经在用的工具里。内网部署的系统由你自己的电脑去连，凭据不出那台电脑，这是云端 Bot 做不到的。

确认模型是这个产品的核心。所有动作过一道闸，对外发布的东西以可编辑草稿给你看，批一份内容计划，按计划发出的每一条不再逐条问。

## 二、对象模型

### 用户

一个账号对应一个人，字段有姓名、邮箱、密码。注册即可用，没有企业域名和管理员开通。用户是所有确认的唯一审批人。

现在。已做到。注册时一并建好本机电脑和主助理。`users` 只剩姓名、邮箱、密码，`team_name` 和登录页的企业文案都删了。

### 电脑

Bot 干活的地方，每人两台，本机和远程。

- **本机。** 你的 Mac，装 App 时一起装上电脑代理。国内平台的账号放这里，走你家里的网络出口，封号风险低。合盖就离线。App 经过签名和苹果公证，下载就能装。App 会自己更新，能开机自启。
- **远程。** 你自己的一台云服务器，跑电脑代理、Xvfb 和 Chrome。GitHub、X、资料搜集放这里，你合盖了照样跑。控制面也放在这台机器上。服务器放海外，因为放在上面的 GitHub 和 X 在国内访问不稳。

`computers` 按 `(owner_id, kind)` 各一行，`kind` 是 `local | remote`。字段还有状态（未连接、在线、离线、故障）和最后在线时间。两台都是电脑代理出站连控制面，协议一样。本机每人一台。在第二台 Mac 上登录时，App 先提示原来那台会被顶掉。两台 Mac 同时在线不做。

现在。`computers` 按 `(owner_id, kind)` 唯一，账号页能加一台远程电脑。`runs` 记了派到哪台。每个 (Bot, 群) 选哪台电脑记在 `group_members.computer_kind`，选过就只认那一台，不在线也不改派。没选过时先挑连着的，同一档本机在前。Bot 能自己换电脑。本机由桌面 App 起电脑代理，token 用系统钥匙串里的密钥加密后存在本地。App 只有 ad-hoc 签名，没有公证。自动更新和开机自启都做了，开机自启是 App 应用菜单里的勾选项，默认不开。没有正式签名，自动检查到新版本也装不上，只有手动检查更新时才提示不能自动更新，所以现在实际更新不了。第二台 Mac 登录时先提示会顶掉原来那台，你确认了才顶，被顶的那台停掉代理并提示。远程电脑的部署说明还没在真服务器上跑过。

### 账号

你开给它的一个平台账号，住在某一台电脑的助理专用浏览器里。字段有平台、账号名、所在电脑、登录状态（有效、过期）、权限档。

权限档有四个，只读、可起草、发布要确认、可直接发布，默认「发布要确认」。碰这个账号的活只能派到它所在的那台电脑。有 API 的平台（GitHub、X、邮箱）走 OAuth，凭据只存在控制面，由控制面代为调用，电脑拿不到凭据，模型只看到结果。插件也由控制面代为调用。标了「只在本机」的插件只下发到本机电脑，用来连内网的服务。

现在。账号有平台、账号名、所在电脑、登录状态和四档权限。GitHub 和 X 走 OAuth，令牌加密存在控制面，Bot 只能经账号代理发读请求。X 也能在助理浏览器里登录，由电脑去发。小红书在助理浏览器里登录，本机和远程电脑都行，登录页的画面送到网页上由你操作。邮箱还没接。派活还不看账号。发布时，浏览器里的账号按它所在的电脑走，走 API 的账号由控制面拿令牌直接发。小红书的真发和评论回复没在真平台上验过。插件由控制面代为调用，凭据不下发。标了「只在本机」的插件只下发到本机电脑，只有这种带凭据。

### 集成

白泽和外部系统的一条连接，分两类。

- **渠道。** 人和 Bot 说话的地方，第一批是飞书，之后是企业微信、钉钉、WhatsApp。一个外部会话（飞书群或单聊）绑定一个白泽的群。群消息仍是事实来源，渠道只是群的另一个窗口，网页和飞书里看到的是同一份对话。入站的话走原来的路由和派活，Bot 的回复转发回去。要你拍板的卡在渠道里渲染成互动卡片，在哪一边批都一样，状态只住在控制面。外部用户映射到白泽用户，没映射上的人发的话不派活。
- **业务系统。** Bot 干活时读写的系统，比如 CRM、ERP、OA。有 API 的走插件，由控制面代为调用。内网部署的标「只在本机」，只下发到你的电脑，从你的电脑连进内网。没有 API 的老系统由 Bot 在助理浏览器里操作，登录走画面接管。写操作默认要问，和对外发布同一档。

WhatsApp 的另一方是企业的客户，不是你。Bot 在那里说的每句话都是对客户说的，默认逐条确认。客户不是白泽用户，它的话进群，但它看不到群里别的东西。

现在。业务系统那一类的插件已经有，控制面代为调用和「只在本机」都做了，调用前过审批闸门。没有任何现成的连接器模板，地址要你自己填（#72）。渠道一类完全没有，唯一的外部入口是例行的 webhook（#73 到 #75）。

### Bot

属于一个用户，字段有名称、标签（`tags: string[]`，有数量上限）、一句话描述、头像色、偏好、会做的事（skill）。名称以外都不必填。Bot 分四种角色。

| 角色 | 谁定 | 进团队页 | 留记忆 |
| --- | --- | --- | --- |
| 主助理 | 注册时建好，唯一 | 是 | 是 |
| 队员（内容、社区、增长、排版） | 主助理提议，你确认 | 是 | 是 |
| 临时帮手（资料员、翻译） | 主助理随拉随散 | 否 | 否 |
| 牌友和解说 | 你直接挑、直接换 | 只在游戏项目里 | 是 |

权限挂在账号和项目上，不挂在 Bot 上。多一个 Bot 不多一份权限。

现在。已做到。Bot 有角色、多个标签、头像色和偏好，主助理每人唯一。临时帮手是用完就散的会话，不落成 Bot。

### 项目

你想做成的一件事，比如「白泽开源首发」「小红书起号」「周末德州」。一个项目就是一个群加一张主题任务卡，卡上加目标（数值、单位、截止）和指标（定时读回的数，比如星数、粉丝数）。项目有队伍、计划、例行和成果。

不属于任何项目的事归「日常」，比如每天晚上的简报。你和某个 Bot 的单聊是只有它一个成员的群，留着，不是主入口。

现在。卡上有了目标和指标，GitHub 星数每 6 小时读一次。界面不再显示 `T-xxxx` 编号。别的指标靠 Bot 上报或手填，还不能定时读回。

### 消息

群里的一条记录，是事实来源。类型沿用现在的用户消息、Bot 消息、系统消息、工具调用、审批、交接、skill 提议、花费。加一个可见范围 `visibleTo`，空表示全群可见，游戏里的底牌和线索靠它。

派活拼上下文时按收件 Bot 过滤可见范围。

现在。已做到。消息带 `visible_to`，为 null 是全群可见。读消息一律带收件人，派活拼上下文按收件 Bot 过滤。

### 草稿与内容计划

Bot 要对外发的东西先成草稿。草稿字段有平台、账号、所在电脑、正文、配图、计划发出时间、内容哈希、状态（待批、已批、已发、退回）。内容计划是一组草稿，可以一次批完。

批准记下每条草稿的内容哈希。到点发出时哈希对得上就放行，对不上就回到待批。批内容，不批点击，这样运营的活才能在你不在的时候跑。配图存成附件，不跟着起草的那台电脑走，远程电脑起草的图也能在本机发布。

现在。草稿和内容计划都有了，计划能一次批完。批准记下内容哈希，改过的稿子回到待批，到点只发哈希对得上的。配图存成控制面上的附件，草稿按附件 id 引用，远程电脑起草的图能在本机发布。走 API 的 GitHub 和 X 草稿还不能带图，X 在浏览器里发最多 4 张，小红书最多 9 张。

### 确认与授权

所有工具调用先过一个统一的判定函数，挂在 Pi 的 `tool_call` 上，包括 bash、write、edit、浏览器和 MCP。

```ts
type ActionKind =
  | "read"             // 读网页、读文件、查数据
  | "write_workspace"  // 在它自己的工作目录里写
  | "write_outside"    // 工作目录以外的文件
  | "delete"
  | "shell"
  | "publish"          // 公开发帖、发评论、发 PR
  | "message_person"   // 私信、邮件、加好友
  | "engage"           // 点赞、关注、收藏
  | "spend"
  | "account_security" // 改密码、改绑定、授权第三方
  | "install";

type Verdict = "allow" | "ask" | "deny";

type Grant = {
  action: ActionKind;
  target: AccountId | Domain | PathPrefix;
  scope: "once" | "project" | "until" | "forever";
  expiresAt?: Date;
  projectId?: ProjectId;
};
```

判定按四层走，前一层有结论就不看后面。

1. 禁区。`~/.ssh`、钥匙串、浏览器的登录资料（包括助理专用 Chrome profile 的 cookie 文件）、别的 Bot 的目录一律拒绝，读写都不行，你给了授权也不行。禁区是路径前缀的一张固定表，不是按文件名猜。
2. 硬清单。`spend`、`account_security`、删除你的文件、授权第三方应用，永远问，不接受 `forever`。
3. 你给过的 `Grant`，以及账号的权限档。
4. 默认表。

| 动作 | 工作目录里 | 工作目录外 |
| --- | --- | --- |
| 读 | 放行 | 问。你给过这个目录的授权就放行，比如在某个项目里允许读 `~/Downloads` |
| 写 | 放行 | 问，没有 `forever` |
| 删 | 放行 | 问，没有 `forever` |
| 读网页、查数据 | 放行 | 放行 |
| 其余动作 | 问 | 问 |

工作目录是 `<dataDir>/<botId>/` 下这个 Bot 自己的目录。会话、记忆和 skill 也按 Bot 分开放在 `<dataDir>/<botId>/` 下。产出放在用户级的共享区，你的 Bot 都能用。

bash 命令先解析出动作类别再判，解析不出的当 `shell` 问。运行器放弃一条确认时发上行报文，控制面把那一行改成「已失效」，不能再点。这个 Bot 在同一个群里收到新消息时，它挂着的确认作废。例行和交接触发的确认 10 分钟没人批，按拒绝处理。这两种都在卡上写明原因。

现在。统一闸门挂在 `tool_call` 上，bash、write、edit、浏览器和插件操作都过它。判定按禁区、硬清单、授权和权限档、默认表四层走。bash 先解析出动作，解析不出的当 `shell` 问。运行器放弃的审批，控制面标成已失效。审批卡按结构化视图写人话，不再贴原始参数。授权范围只有单次、本项目、永久，没有限时一档。工作目录里的删除也算硬清单，每次都问。你在同一个群里发了新消息，被派活的那个 Bot 在这个群挂着的确认作废，卡上写「已作废」。例行和交接触发的确认 10 分钟没人批按拒绝处理，你当面发起的不过期，放满一天补一条提醒。别的 Bot 的目录在禁区里，批了也读不到。用户级的共享区在 `<dataDir>/shared`，你的 Bot 都能读写。

### 例行

到点替你做的一件事。字段有名称、做什么、触发器（定时、webhook）、所属项目（可空，空即日常）、执行者（主助理可换的 Bot）、边界（只读、草稿等你批）、状态、上不上首页、运行记录。

状态是 `on | paused | auto_paused`。一条例行的结果连续三次没人看，它自己停，和你手动暂停分开显示。项目归档时它的例行一起停。

现在。例行挂在项目上，项目为空即日常。字段有执行者、边界、三态、上不上首页和运行记录。三次没人看自己停，项目归档时一起停。执行者能在编辑界面换，运行记录和调度游标不动，下一次到点派给新的，换人前已经触发的那次仍由原来的做完。项目上的例行，新执行者得已在项目群里，不在就拒绝；日常的跟着执行者走，改发进它的单聊。牌友和老白不能当执行者。删 Bot 时它名下的例行转给主助理，它手上还在跑的那次收成失败。

### skill 和偏好

skill 是 Bot 会做的一件事，只在对话里管，界面上能看不能配。Bot 干完同类的活提议存；你让它学某类活或去装个技能，它找公开的 SKILL.md（比如 GitHub 上的 anthropics/skills）改写成中文步骤，出一张带原链接、列全部步骤的装技能卡；你说改或删哪个，它出改或删的卡。都是你点了才生效，随 config 下发成 `SKILL.md`。来源有对话里存的、从某处装的、模板带来的，旧数据里还有你教的和例行里存的。

偏好是你在单聊里教 Bot 的一句话，比如「标题别超过 15 个字」。字段有正文、来源消息、是否私人。Bot 要记一条偏好时先出一张确认卡，你点了才记下。记下的偏好可见、可删，写作时套用。

品牌手册是所有 Bot 共用的一份资料，写产品事实、口吻、禁区和你的素材。你改过的草稿，改了什么记进这里。

现在。skill 的存、装、改、删都走对话里的卡，Bot 页头「它知道的」里每条能点开看步骤、来源和用过几次，设置栏里没有技能入口；装来的记下原链接，点得开。偏好在单聊里记，能删、能标私人，每次模型请求都带上。Bot 记偏好先出确认卡，你点「记住」才写入。品牌手册所有 Bot 共用，你改过的草稿把改动记进去。

### 模板

分享出去的 Bot 配方。一定带名字、标签、描述。默认带、可取消的是 skill 和你提炼的插件（带配置，不带登录）。偏好逐条勾，标了私人的默认不勾。永远不带账号登录、对话记录、文件、项目。

导入即复制，得到一个独立的新 Bot，原作者以后再改不同步。第一版没有版本号，没有公开模板库。

现在。已做到。分享弹窗里 skill 和插件默认带，偏好逐条勾，私人的默认不勾。包里没有任何 id 和凭据。导入建一个独立的新 Bot，插件要重新授权才能用。

### 用量

每次 run 结束记一条，字段有 Bot、项目、时间、步数、模型用量、折算金额。设置里按月、按 Bot 汇总，有月预算，超预算先停例行。

现在。已做到。每次 run 记步数、token 和金额，花费按 run 算增量。设置里按月、按 Bot、按项目汇总。有月预算，超了先停例行的自动触发。

## 三、核心流程

### 注册和第一次打开

对应 U1。用户注册后进「今天」页。App 调「注册本机」接口拿电脑 token，存进钥匙串，经 stdin 交给电脑代理，不走环境变量。主助理在注册时建好。远程电脑可以之后在设置里加。

### 建项目

对应 U2、U8。你说一句想做成什么事，主助理回一张方案卡，写项目名、目标、队伍、要用的账号、节奏、第一步。点「开始」才建，和 `skill_offer` 一样先提后存。建项目时不逼你连账号，等第一条要发的内容写好再请你登录。没有表单式的新建。

### 派活

你在首页说的话进主助理的单聊，在项目页说的话直接落进那个项目的群。主助理决定这句话谁接，队员之间用现在的 @、交接和首席机制接力，这些在界面上收成过程里的一行。

路由、群回合、回路上限沿用 `control-plane/src/agent/routing.ts` 和 `group-turn.ts`，设计理由在 `packages/control-plane/README.md`。项目群里主助理就是首席。

### 从 IM 里说话

对应 U16、U17。你在飞书群里 @ 白泽的机器人说一句话，渠道适配层把它写成那个群的一条用户消息，之后和在网页上说一模一样。Bot 的回复和要你批的卡回到同一个飞书群。你在飞书里点批准，网页上那张卡同时变成已批。适配层不做路由、不存状态，只翻译消息和卡片。

客户在 WhatsApp 上发来的话按同样的路子进群，派给负责这个渠道的 Bot。Bot 的回复先成草稿给你批，批了才发给客户。超过平台允许自由回复的时限，Bot 只能从审核过的模板里选。

### 过闸

Bot 调任何工具都先过第二节的判定。`allow` 直接执行。`ask` 在「等你确认」里出一张卡，工具调用挂起等结果，你批了从断点继续。`deny` 让工具抛一个中文错误，Bot 看到原因换路子。暂停和接管也走这道闸，挂起而不是 `abort()`。

你当面让 Bot 做的事，卡不按时间过期。例行和交接触发的卡 10 分钟没人批，按拒绝处理。这个 Bot 在同一个群里收到新消息时，它挂着的卡作废，卡上写明原因。这三条只管工具调用挂起时出的卡，草稿和内容计划不受影响。边界见 `plan/交付补强架构.md`。

### 草稿和内容计划

Bot 调 `publish` 类工具时不直接问「允许吗」，而是生成草稿。卡片上显示平台、账号、正文和配图，你直接改字再批。一份计划的 N 条一次批完。你改过的地方记进品牌手册。

### 开账号和登录接管

对应 U3、U7。每台电脑一个助理专用的 Chrome profile，Bot 通过 CDP 在后台标签页操作，不抢你的鼠标键盘。要登录时电脑在后台开平台的登录页，把这一页的实时画面送到网页上，你在画面里扫码或输密码，验证码和二次验证也由你来。本机和远程电脑走同一条路，远程电脑上的 Chrome 画在 Xvfb 里，你在网页上看到的画面一样。电脑每 250ms 查一次登没登上，登上就收起画面、关掉登录页，15 分钟没登上也收起。本机电脑上登录时，助理 Chrome 的窗口也同时拉到前台，在窗口里直接操作也行，登完退回后台。画面帧和你的按键只在电脑和网页之间转发，不进库、不进日志，也不进模型。登录过期时只停碰这个账号的活。登录态按人共享，你登进去的网站，同一台电脑上你的每个 Bot 都能用，设置页写明这一点。

Bot 在网页上卡在它过不去的地方（滑块、验证码、要人确认的页面）时，调 `browser_ask_user` 把这一页借给你。群里出现一张接手卡，写哪个 Bot、为什么、页面在哪台电脑上，任何页面的右下角也有一条提示。画面不自动弹出，你点「打开画面」才摆出来，本机电脑的窗口也不自动拉到前台，要在窗口里弄就点画面上的「到本机窗口操作」。弄完点「交还给 Bot」，Bot 拿回这一页接着做；点「不弄了」，Bot 知道你没接手，换办法或停下。接手挂着时你在这个群里发了新消息，这次接手作废，Bot 先处理新消息。30 分钟没交还按没接手算。借出去的那一页 Bot 自己碰不了，同一台电脑上别的活照跑。整页同一时刻只摆一块画面，登录和接手同时在时摆你最后点的那块。

浏览器工具写在运行器里，参照 Pi 官方 `pi-skills/browser-tools` 的裸 CDP 做法，不走 MCP。

### 例行

对应 U10。在对话里说一句，主助理回一张确认卡，写清时间、项目、执行者、边界，点「加上」才生效。改例行也回对话，输入框预填一句话。调度器沿用现在的，派到执行者该去的那台电脑，远程电脑在线就不怕合盖。

### 分享与导入

对应 U14。分享弹窗默认一段话说清带什么、不带什么，底下「复制链接」。导入得到新 Bot，接导入者自己的账号。插件导出成不含凭据的配置。

### 牌局

对应 U15。发牌、底池、行动合法性、结算全部在控制面的确定性引擎里，模型只负责决策和台词。牌力和位置由代码算好再给模型，模型裸打很弱。你的手牌只有你和引擎看得见。无真钱，无筹码兑换。

剧本杀排在德州之后，用现成剧本，主持只拿当前阶段能公开的内容，真相放在引擎里。

## 四、界面规矩

### 露什么

一条信息露不露出来，只看它会不会改变你下一步的动作。

- **明面上。** 草稿正文，发到哪个平台哪个号，什么时候发，发出后的链接和数据，项目离目标还差多少。
- **收起来。** 做了哪些步骤、哪个 Bot 做的、用了什么工具，收成一行「做了 N 步」，展开是人话步骤，再往下是右侧检查器。runId、模型名、原始参数只在检查器的「高级」里。
- **删掉。** 任务编号、系统小字、每轮花费（改成设置里按月汇总）、「消息来自」、审批卡里的原始 JSON。

### 首页「今天」

用原型里的方案 A「今天清单」。另外两种排法不做，对话优先会让新消息把确认卡冲走，项目看板要多点一下才看到草稿。看板的指标一览放进项目页。

顶上一句问候和输入框。左栏「等你确认」和「刚做完」，右栏「在进行」和「接下来」。「在进行」每个项目一行，带进度条。「接下来」只列已排期的发布和标了上首页的例行。

### 项目页

从上到下六块。对应 U9。

1. 项目名、目标、进度条和本周变化。
2. 项目自己的输入框。
3. 最近一轮对话紧贴在输入框下面，更早的折成「更早 N 轮」。
4. 等你。只放这个项目的卡，正在做的事以一行灰字出现，写好变成卡。
5. 本周计划、下一步、成果。成果按时间倒序，数据来自发布记录和计划状态，不是历史消息。
6. 折起来的「队伍 N · 例行 N」。

消息在这一页只是指令，结果落进固定块。

### Bot 页

在团队页点一张 Bot 卡片，进去就是和它单聊。顶上名字、一句话描述，右边「编辑」和「分享」。下面一行「它知道的 · 记住 N 条 · 会 N 件事 · 在 N 个项目」，点开才列出来，技能能再点开看步骤、来源和用过几次，底下一句「想加、想改、想删，直接跟它说」，没有新建、编辑、删除按钮。插件勾选、模型不在这里露出。

### 设置

左下角齿轮，一个弹窗五页。Bot 的事去 Bot 页，你的事去设置。现在通用页是账户（名字、邮箱、退出登录）、外观、一个总的通知开关和夜里免打扰，浏览器里另有一行通知权限，没有开机启动、菜单栏常驻、语言和时区。开机启动在桌面 App 的应用菜单里勾，没进设置。账号与电脑页写明了浏览器登录态由你的 Bot 共用。插件页有「只在本机用」开关。数据与隐私页只有导出和删账号，没写工作记录和记忆存在哪、留多久。

| 页 | 放什么 |
| --- | --- |
| 通用 | 三种通知开关、夜里免打扰、菜单栏常驻、开机启动、外观、语言、时区 |
| 账号与电脑 | 按电脑分组列账号，每个号只显示当前那一档，点开才换。页尾加电脑、本机能碰的文件夹、永远要问的四件事。写明浏览器登录态由你的 Bot 共用 |
| 插件 | 内置的和你提炼的分开标，写清谁在用。每个插件有「只在本机」开关，打开后只下发到本机电脑 |
| 用量 | 本月花费和预算，按 Bot 分 |
| 数据与隐私 | 导出全部数据，工作记录和记忆存在哪、留多久，删账号。截图原图和超长输出只留摘要，删 Bot、删群连带删掉它的记录，删账号全删 |

### 通知和菜单栏

通知只在三种时刻发，要你确认、做完有成果、卡住了。夜里免打扰时攒着。菜单栏常驻，数字只数等你确认的事，点开能直接批，也能说一句。

## 五、运行架构

```
桌面 App（Electron，界面和 Web 同一份，签名公证，自动更新）
  │ HTTP /api，WebSocket /api/ws
  ▼
控制面（Hono + Postgres，放在你的远程服务器上）
  │ WebSocket /agent，config 下发
  ▼
电脑代理 ×2（本机、远程）
  └─ Bot 运行器：每个 Bot 每个群一份 Pi 会话，同一时刻只有一台电脑在写，统一闸门，浏览器工具
       │ 模型请求走控制面 /gateway/v1
       ▼
     模型上游（多模型：闸门分类用便宜的，规划用强的，截图能进）
```

沿用 v0.1 的部分。控制面、电脑代理、Pi 运行器这条链路，出站连接，模型网关换 key 换模型，群消息是事实来源，Pi 的会话文件落在 `<dataDir>/<botId>/` 下，`~/.pi` 不出现新文件。

改了的部分。

- 控制面从「我们的云」改成你自己的远程服务器，以后对外再换托管部署。
- 过夜机改成你自己的远程电脑，一台机器只有你一个人，不再按用户分进程。
- Bot 不再用你屏幕上的浏览器，改用每台电脑一个助理专用 Chrome profile。
- config 从整份换运行器改成按 Bot 增量对账，只重建改了的那个 Bot 的会话，没在跑的才重建。
- 网关从一个上游一个模型改成多模型，收图片。
- 控制面和电脑代理之间要送达的报文共用一套可靠信封，带序号、确认、补发和连接代际，断线重连后补齐。握手带协议版本，控制面拒收旧版本的代理并提示升级。控制面能往下发取消。
- 工作记录改存控制面，电脑上 Pi 的 JSONL 降成可重建的缓存。同一个 Bot 在同一个群里，同一时刻只有一台电脑持租约在写，换电脑接着干，不分叉。记忆库带召回，产出存成附件，留存规则见第四节「设置」的数据与隐私页。
- 插件由控制面代为调用，电脑拿不到凭据。标了「只在本机」的插件只下发到本机电脑。
- 会话、记忆和 skill 的目录按 Bot 隔离，Bot 读不到别的 Bot 的目录。产出放在用户级的共享区，浏览器登录态按人共享。
- 运行器的串行队列从按 Bot 改成按 Bot 和群，同一个 Bot 在两个群里的活互不等待。
- 控制面加一层渠道适配，每家 IM 一个适配器，把外部会话绑到白泽的群。入站翻成群消息，出站订阅群消息和卡片状态的推送。核心的路由、派活、审批不知道渠道的存在。

现在。从可靠信封到串行队列这五条是 2026-10-13 定的交付补强，都做了。要送达的报文都走可靠信封，审批、交接和发布结果断线重连后各只落一次。下行有取消。握手带协议版本，低于下限的代理被拒并提示升级。每个 (Bot, 群) 一份租约，会话上传成控制面的工作记录，换电脑时按服务器记录重建，不分叉。偏好和品牌手册仍每次整份带上，另有 `recall_memory` 查这个 Bot 在别的群里的公开聊天。截图原图和超过 16KB 的输出上传前换成摘要。删 Bot、删账号时控制面上的工作记录和附件一起删，删 Bot 时电脑上它的目录也删，删账号不删电脑上的会话文件。没有删群，多 Bot 群只能解散，解散后消息和任务卡都留着。运行器按 (Bot, 群) 分道，同一个 Bot 在两个群里的活并行。最后一条渠道适配还没做（#73）。边界见 `plan/交付补强架构.md`。
