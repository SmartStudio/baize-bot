# 白泽 Bot 上手

这一页带你从零走到三件事做完。你在首页对主助理说了第一句话，连上了一个平台账号，开了第一个项目。

读者是第一次用白泽 Bot 的人，不需要会写代码。页面里几处写着「**现状**」，那是今天产品里还没有入口，或者还没做完的地方。照实写出来，免得你找不到按钮。

## 开始之前

先备好这几样东西。

- 一个在运行的白泽控制面，和它的地址。自己在开发机上试用时，地址是 `http://localhost:3001`。别人部署的，向管理员要地址。管理员的部署说明在 [deploy/README.md](../deploy/README.md)。
- 一台 Mac，装好白泽 App。**现状。** 目前没有下载地址。App 要在仓库里自己打包，先在仓库根目录跑 `pnpm install`，再跑 `pnpm --filter @baize/desktop package`。它只打 macOS 版，用临时签名，成品 `Baize.app` 在 `packages/desktop/dist/pack` 下面的目录里。
- 连小红书时，要有 Google Chrome，装在 `/Applications/Google Chrome.app`。
- 连 GitHub 或 X 时，要管理员已经在控制面上配好对应的应用。

## 1. 注册白泽账号

如果控制面不在这台 Mac 上，先改 App 的连接地址。App 默认连 `http://localhost:3001`。

1. 打开白泽 App。
2. 点菜单栏的 **白泽**，选 **控制面设置…**。
3. 在 **地址** 里填管理员给你的地址。
4. 点 **保存并重启**。

地址不是本机（`localhost`、`127.0.0.1`）时，必须以 `https` 开头。写成 `http` 会弹出错误框，写着「远程控制面必须使用 https」。

保存后，App 会清掉已存的电脑 token 并重启。新地址上是另一套账号，所以接下来要在新地址上注册或登录。

然后注册。

1. 在白泽 App 里看登录页，标题是「欢迎回来」。
2. 点「还没有账号？」旁边的 **注册**。
3. 在「创建账号」页填 **邮箱**、**密码** 和 **姓名**。
4. 点 **注册**。

**你会看到。** 页面直接进到首页，也就是侧栏里的 **今天**。最上面是问候，比如「陈，早上好」，名字取你填的 **姓名**，时段词随钟点变成「夜深了」「下午好」或「晚上好」。问候下面一行写着「没有要你处理的事，其余在按计划跑。」再往下，**主助理** 那一行有它的第一句话「想让我帮你做成什么事？说一句就行」。下面四块 **等你确认**、**刚做完**、**在进行**、**接下来** 都是空的，分别写着「没有要你处理的事」「还没有新成果」「现在没有进行中的计划」「还没有排期」。

注册失败时，表单里出现红字。最常见的一条是「这个邮箱已经注册过了」，换一个邮箱，或者回登录页直接登录。

**现状。** 系统不检查密码强度，只要求不为空，请自己选一个够长的。注册对任何能打开这个地址的人开放，没有邀请码，没有邮箱验证，也没有管理员审批。开放注册还是邀请制，项目组还没定。

## 2. 配对电脑

主助理和你的 Bot 在你自己的 Mac 上干活，由一个常驻的电脑代理接活。把这个电脑代理和你的账号连起来，就叫配对。

**现状。** 网页上没有「配对」按钮。配对只在白泽 App 里自动完成。你在 App 里注册或登录成功后，App 自己向控制面申请本机的 token，用系统钥匙串加密后存在本机，再启动电脑代理。所以第 1 步要在 App 里做。在浏览器里注册也能进首页，但电脑不会上线，之后在 App 里登录一次同样能配对。

你不用点任何东西，只需要确认配对成功。

1. 点侧栏最下面「你」旁边的齿轮。
2. 在设置窗口的导航里点 **电脑**。

**你会看到。** 一行 **本机**，右边是状态。刚注册、电脑代理还没连上时是 **创建中**。连上后变成 **在线**。电脑代理断开，或者控制面超过 45 秒收不到它的任何消息，状态变成 **休眠**。

出错时有两种表现。

- App 弹出标题为「电脑代理启动失败」的对话框。正文可能是「电脑代理 45 秒内没有被控制面接纳」，也可能是「申请电脑 token 失败」加一个状态码，或者「系统钥匙串不可用，不能安全保存电脑 token」。把正文原样发给管理员。退出 App 再打开，它会再试一次启动。
- **本机** 一直停在 **创建中**，没有弹窗。配对只在 App 里登录或注册成功后发生。如果你是在浏览器里注册的，在 App 里登录一次。

一个账号只有一台本机。每次在 App 里登录或注册，控制面都会给这台本机换一个新 token，旧 token 当场作废。

**不用 App 的办法。** 工程师可以在控制面所在的机器上跑 `pnpm --filter @baize/control-plane computer-token -- 你的邮箱`，拿到 `COMPUTER_ID` 和 `AGENT_TOKEN`，填进仓库根目录的 `.env`，再用 `pnpm dev --agent` 起电脑代理。步骤在仓库 [README.md](../README.md) 的「跑起来」一节。

## 3. 在首页说第一句话

1. 点侧栏的 **今天**。注册后你已经在这页。
2. 点输入框。灰字是「对主助理说一句，比如「下周多发点小红书」」。
3. 写一句话。第一句不必是正事，「你好，你能帮我做什么？」就够了。这一句只用来确认电脑和模型都通了。
4. 按回车，或者点输入框右边的发送按钮。

输入框下面还有两个模板按钮，**推广一个产品** 和 **运营一个号**。它们只把一句示范的话填进输入框，不会发送，你可以改了再发。

灰字如果是「主助理还没准备好」，输入框是锁着的。主助理准备好后它会自动解锁。

发送失败时，输入框下面出现「没发出去，请重试」，你写的话还留在输入框里。再发一次。

**你会看到。** 输入框清空。过一会儿，输入框上方 **主助理** 那一行换成它的新回复，右边带着时间。点这一行，进主助理的单聊，能看到整段对话。你也可以随时点侧栏的 **主助理** 进去。

### 第一句话没有回音

打开侧栏的 **主助理**，在对话里找带警示三角的红色提示。

- 「电脑不在线，这条没派出去，电脑回来后再说一次」。你的 Mac 上电脑代理没连上。回第 2 步，等 **本机** 变成 **在线**，再发一次。你有不止一台电脑时，这句换成「你的电脑都不在线，这条没派出去，有一台回来后再说一次」。
- 「电脑上的白泽版本和控制面对不上，这条没派出去，把电脑上的白泽升级或重启后再说一次」。App 和控制面不是同一个版本。升级或重启 App。
- 「模型没回话」，有时紧跟「，上游状态码 401」这样的数字，后面是「检查控制面的上游地址、key 和模型映射」，括号里列着 `UPSTREAM_BASE_URL`、`UPSTREAM_API_KEY`、`GATEWAY_MODELS`。这是控制面连模型服务出了问题，你自己改不了。把整句话转给管理员。

## 4. 连一个平台账号

这一步可以跳过，等开完项目再回来也行。开项目时，没连的账号不会拦着你，要等第一条要发的内容写好了，才会请你登录。

入口在设置窗口。点侧栏最下面的齿轮，再点左边的 **账号**。也可以点侧栏的「你」，在菜单里选 **设置**。

页面最上面有三个按钮，**接入 GitHub**、**接入 X**、**接入 小红书**。三个平台连法不同。

### GitHub 和 X

1. 点 **接入 GitHub** 或 **接入 X**。
2. 页面整页跳到平台的授权页。在那里点同意。
3. 授权后回到白泽首页。

**你会看到。** 首页出现提示「GitHub 账号接好了」（X 同理），旁边有 **看账号** 按钮。点它进 **账号** 页，多出一行「GitHub · 你的用户名」，下面写着「在本机 · 权限「发布要确认」」和「已登录」。你有远程电脑时，「在本机」会换成「在远程电脑」，有主机名的话主机名跟在后面。

可能遇到的提示有三条。

- 「你在 GitHub 那边没有同意授权，账号没接上」。你在授权页点了拒绝。再点一次 **接入 GitHub**。
- 「这次 GitHub 授权过期了或不是从这里发起的，再点一次接入」。再点一次 **接入 GitHub**。
- 「GitHub 授权没成，账号没接上，稍后再试一次」。稍后再试。

管理员没配好应用时，点按钮后不会跳去平台。页面上出现控制面返回的一行内容，写着「管理员还没配 GitHub 应用，连不了 GitHub」。X 的写法一样，把名字换成 X。把这句话转给管理员。

**现状。** 授权回来时，控制面要靠浏览器带回的登录状态认出你。从白泽 App 的窗口里发起授权，仓库里没有专门处理它的代码，也没有测试，能不能成功没有证据。

### 小红书

小红书在助理浏览器里登录。助理浏览器是电脑上一个助理专用的 Chrome，不是你平时用的那个浏览器。登录页开在你选的那台电脑上，画面送到网页里，你在画面上扫码，或者输入手机号和验证码。输入直接发到那台电脑上的这一页，你的密码不经过 Bot。

1. 点 **接入 小红书**。名下有两台以上电脑时，按钮下弹出一张小菜单，选在哪台电脑上登录。本机排第一，不在线的电脑是灰的，后面写着「休眠中」「还在创建」或「出错了」。只有一台电脑时不弹菜单。
2. 等网页上弹出画面，里面是小红书登录页。
3. 在画面里扫码，或者输入手机号和验证码，登录小红书。登录页开在本机时，画面上还有 **到本机窗口操作**，点它把 Mac 上助理浏览器的窗口摆到前台，在窗口里扫也行。不想登了点 **不登了**。

**你会看到。** **账号** 页多出一行「小红书 · 未登录」，第二行写着号挂在哪台电脑上。行上的按钮写着「等你扫码…」，旁边的提示是「登录窗口已在本机打开，扫码后这里会变成已登录。」选的是远程电脑时，「本机」换成「远程电脑」加主机名。登录成功后，画面自己收起，这一行变成「已登录」，按钮消失。

**接入 小红书** 点不了时，按钮旁边写着原因。

- 「先在下面的「电脑」里加一台电脑，才能接入」。账号页还没有读到任何一台电脑。回第 2 步配对本机，或者在 **电脑** 里加一台远程电脑。
- 「本机休眠中，开不了登录窗口」。你只有一台电脑，它现在不在线。「还在创建」「出错了」同理，等它在线再点。

扫码没成功时，账号行上有一条提示。

- 「本机不在线，打开电脑上的白泽后再点登录。」打开 App，等 **本机** 在线，再点 **打开登录窗口**。号挂在远程电脑上时，「本机」换成远程电脑的名字。
- 「登录页已收起，要登再点一次。」画面出现过又收起了，结果还没到。要登就再点一次 **打开登录窗口**。
- 「登录没成。登录窗口出错或被关掉了，账号状态没变，可以再点一次。」再点一次 **打开登录窗口**。
- 「登录没成。登录窗口开了很久还没登上，已经收起，账号状态没变，可以再点一次。」登录页开着 15 分钟没登上就收起。再点一次。
- 「没等到登录结果，可以再点一次登录。」同上。
- 「登录窗口没打开：」后面跟着原因。照原因处理，或者转给管理员。

### 选权限档位

每个账号行都能点开，里面是四个权限档位。新账号默认是 **发布要确认**。

- **只读**，只看数据和评论，不写任何东西。
- **可起草**，它写好草稿放在首页，你自己去发。
- **发布要确认**，它会发，但每条对外内容先给你看。批一份计划就不再逐条问。
- **可直接发布**，这个号发帖不再问你，每晚简报里汇总。私信和花钱仍然问。

小红书的 **可直接发布** 是灰的，旁边写着「平台 2026-03-10 起封 AI 托管账号」。小红书只能选前三档。

账号还没连时，页面写着「还没有接入的平台账号」。

## 5. 开第一个项目

1. 点侧栏 **项目** 那一行右边的加号。
2. 在弹出的 **新项目** 窗口里，输入框灰字是「比如「把抖音号做起来，年底 1000 粉」」。写一句你想做成的事，比如「推广白泽的开源仓库，年底 1000 星」。
3. 点 **交给主助理**。

窗口里的说明是「名字、队伍、要用的账号、多久跑一次，主助理排成一张方案卡给你看。你点开始就开工，不用先填表。」

**你会看到。** 页面跳到主助理的单聊，你的话是最新一条。过一会儿，主助理回一张方案卡。卡的标题是「新项目 · 项目名」，下面一行「主助理的方案 · 名字点一下就能改」。卡上依次是 **目标**、**队伍**、**平台**、**节奏**、**第一步**，底部写着「对外发的每一条照样先给你看。」

**平台** 一栏看你连了什么。连了的显示「X · 你的用户名」，没连的显示「X · 第一条内容写好时请你登录」，这个平台系统还不支持的写「平台名暂不支持」，项目不碰账号的写「不碰任何账号」。

主助理会判断你这句话归谁。你说的如果不像一件要做成的事，它可能直接回答，不出方案卡。

对方案卡做下面任意一件事。

- 改项目名。点卡上的名字，改完点别处。名字最长 40 个字。
- 想改别的，点 **改一下**。输入框里会出现「改一下：」，接着写你的想法，发给主助理。
- 满意了，点 **开始**。

**你会看到。** 页面跳到新项目页，侧栏的 **项目** 下多了这个项目。回到主助理的单聊，方案卡已经折成一行「项目已开始」，旁边有 **去看看** 按钮。点开始时，系统一次建好这些东西。

- 队伍里的 Bot。
- 一个项目群，主助理是首席。
- 一张主题任务卡。
- 两条例行，「周一 09:00 排本周计划」和「周五复盘」（周五 17:00）。

两条例行按控制面所在机器的本地时区计时。新建的例行不会立刻跑一次，要等到下一个时刻才跑。控制面停机期间错过的时刻不会逐个补跑。

项目页从上到下是这几块。

- 最上面是项目名、目标、「节奏：…」和清单进度（比如「0 / 1 项」），右边有 **进项目群** 按钮。
- 往下是输入框，灰字是「对这个项目说一句，比如「这周多发两条小红书」」。
- 再往下是 **等你** 和 **成果**。新项目的 **成果** 里写着「还没有发出去的成果」。有计划或下一件事时，还会多一块 **本周计划** 或 **下一步**。
- 最下面是一行折起来的「队伍 N · 例行 2」。点开能看到队员，和两条例行各自的下次时间。

**现状。** 方案卡只出现在主助理的单聊里，首页的 **等你确认** 里没有它。点开始之前找不到卡，就点侧栏的 **主助理** 回去看。

## 你现在有了什么

你有一个已配对的本机，一个能回话的主助理，一个或几个平台账号，和一个带队伍与两条例行的项目。接下来在项目页的输入框里说一句话，就是这个项目的第一轮。

### 2. 配对电脑

- 配对只在 App 里做。登录或注册请求返回 2xx 后，App 先通过 `/api/me` 核对账号，只复用 `ownerId` 匹配的本地凭据；换账号或旧凭据没有 `ownerId` 时先停旧代理再申请本机 token，遇到 409 由用户确认是否让另一台 Mac 退出。被顶号后删除凭据，删除失败则尝试写失效标记并照常提示；本机确认配对后保存凭据失败，随后提示「凭据保存失败，请重新登录」。旧提示中的重新连接会等待在途配对，并在当前凭据已在线时直接结束。证据在 `packages/desktop/src/main.ts` 的 `provision`、`loadCredentials` 和 `handleDisplaced`。
- App 启动时用已存的凭据，没有就先问 `/api/me` 再申请 token。证据在 `packages/desktop/src/main.ts` 的 `main` 和 `launchSavedAgent`。
- 每次申请，控制面都给本机换新 token，旧的作废。证据在 `packages/control-plane/src/http/app.ts:447-454`。
- token 用系统钥匙串加密后存在本机。证据在 `packages/desktop/src/main.ts` 的 `saveCredentials` 和 `loadCredentials`。
- 电脑代理的启动配置经 stdin 传入，不放进环境变量。证据在 `packages/desktop/src/main.ts` 的 `startAgent` 和 `agentEnv`，以及 `README.md` 「跑起来」一节。

- 电脑状态有四种，在线、休眠、创建中、失败。证据在 `packages/web/src/components/messages/content.ts:14-19`。
- 控制面 45 秒收不到电脑代理的任何消息就记为休眠。证据在 `packages/control-plane/src/agent/hub.ts:53`。
- App 弹窗标题「电脑代理启动失败」，正文来自配对、凭据保存或代理启动的错误。证据在 `packages/desktop/src/main.ts` 的 `requestConnection`、`postLocalComputer`、`saveCredentials`、`startAgent` 和 `launchSavedAgent`。
