# 白泽 Bot 开发计划 v0.1

日期 2026-09-18。依据是 spec/规格.md 和 bot-application-prototype/白泽 Bot.dc.html。这份计划是一张按顺序打勾的清单。每个里程碑结束在一个能看见的结果上，看不到结果不进下一个。时间和人手还没定，所以每个里程碑给的是粗估人周，用来帮你排人，不是承诺。

## 怎么读

一个方框是一个工作单元。每个方框写明验收它的证据，一段录屏、一条日志、一个通过的测试或一个网址。方框只在证据存在时打勾。里程碑按依赖排，M1 之前的顺序不能换，M5 之后的顺序可以按人手调。

三条工作线可以并行：控制面和客户端一条线，云电脑和桌面一条线，Bot 运行器一条线。每个里程碑标了它落在哪条线上。

## 首个场景的验收剧本

这是 M11 结束时要跑通的完整剧本。前面每个里程碑各覆盖它的一段。

1. 陈默用账号密码登录，侧栏看到 5 个 Bot。
2. 点加号建群，主题任务写「Globex X3 × 200 订单」，拉小服、小销、小采，写一句话说明，建群。群顶部出现任务卡 T-2482。
3. 在群里 @小服 说「Lisa 要 200 台 X3，10 月 30 日前交，先查库存和排产」。小服在自己的桌面里打开 ERP 查数据，工具调用出现在群里，回结论和两个方案。
4. 陈默回「分两批，回复先给我看」。小服起草邮件，走到发送时群里出现审批卡「对外发送」。陈默点批准，邮件发出，群里出现「你批准了发送」。
5. 小服发交接报文给小采，报文写做了什么、没做什么、下一步。小采确认，任务卡当前经手变成小采，清单里「供货确认」变成小采的。
6. 小采查供应商门户时登录过期，停下请陈默接管。陈默在桌面面板切到小采的桌面，接管，登录，交回。小采从断点继续。
7. 小销的例行任务「每日线索早报」在早上 9 点跑了一次，结果回到小销的群里。
8. 小服干完后问「这套流程存成 skill 吗」，陈默点存。Bot 设置的会做的活里出现「Globex 报价」。
9. 设置的用量页按 Bot 列出本周花费。

## M0 仓库与脚手架

**依赖。** 无。

**做什么。**

- [ ] 建 pnpm monorepo，五个包：`control-plane`、`web`、`computer-agent`、`bot-runner`、`shared`。`shared` 放规格第一部分的全部对象类型，其他包只从这里引用类型。
- [ ] `control-plane` 用 Node 加 TypeScript，HTTP 框架、PostgreSQL、迁移工具各选一个，写进仓库 README。
- [ ] `web` 用 React。把原型 `_ds` 目录里的 tokens 和 styles.css 搬进来，作为唯一的样式来源。
- [ ] CI 跑类型检查、lint、单元测试、`web` 的 Playwright 冒烟。
- [ ] 本地一条命令起全部服务，含一个 PostgreSQL。

**你看到。**

- [ ] 浏览器打开本地 `web`，空白主窗口用原型的字体、颜色和圆角渲染出来，侧栏和三栏布局在。
- [ ] CI 在一个空提交上全绿。

**验证。**

- [ ] `shared` 里每个对象有一个类型测试，非法状态编译不过。
- [ ] Playwright 冒烟截图和原型 02 屏的空状态并排看，布局一致。

## M1 两个技术验证

**依赖。** M0。这一步的产出是结论，不是产品代码。两个验证并行，各自一人。

**验证一，Pi 嵌入。**

- [ ] 在一个 Node 进程里用 `createAgentSession` 起两个 AgentSession，各自的 cwd、会话文件、模型不同。
- [ ] 用扩展注册一个自定义工具，在 `tool_call` 事件里拦截它，等待一个外部 HTTP 请求给出批准或拒绝，拒绝时返回 block。
- [ ] 起一个最小的 OpenAI 兼容网关，把它注册成 Pi 的自定义供应商，两个会话的模型调用都经过它，网关记下每次的 token 用量。
- [ ] 把一段群消息作为提示送进会话，把流式文本和工具事件转成规格里的消息类型。

**验证一，你看到。**

- [ ] 一段录屏：两个会话同时跑，一个被拦截等批准，另一个不受影响。网关日志里两个会话的用量分开。

**验证二，云电脑。**

- [ ] 在一台支持 KVM 的机器上用 Firecracker 起一台 Debian microVM，装 Xvfb、窗口管理器、Chromium、VNC 服务。
- [ ] 写最小的电脑代理，启动时出站连到一个测试服务，转发 VNC 流。
- [ ] 开两个桌面，各跑一个 Chromium。在浏览器里通过测试服务同时看到两个桌面的画面，并能在其中一个里输入。
- [ ] 试规格待定项 3 的两个登录态共享方案，记录哪个可行、切换代价多大。
- [ ] 记录一台宿主机的内存和 CPU 能跑几台这样的电脑。

**验证二，你看到。**

- [ ] 一段录屏：浏览器里两个桌面并排，一个桌面登录某站点后，另一个桌面打开同站点已是登录态。

**收尾。**

- [ ] 把两个验证的结论写回 spec/规格.md 第五部分，关闭待定项 1、3、6。定不下来的写明原因。

## M3 单 Bot 派活闭环

**依赖。** M1 的结论、M2。这是关键路径上最重的一步，三条线都要动。

**做什么。**

- [ ] 控制面：群和消息表，消息的 WebSocket 推送，首次登录时创建云电脑的任务队列。
- [ ] 电脑代理：正式版，出站连接、心跳、指令通道、状态上报。
- [ ] Bot 运行器：正式版，按控制面下发的 Bot 列表起 AgentSession，收群消息、回流式文本、回工具事件，运行结束回用量。
- [ ] 模型网关：正式版，供应商可配，每次调用记用量到用量记录表。
- [ ] `web`：2a 对话页，用户消息、Bot 流式消息、工具调用卡、花费卡、Bot 设置栏里的名称标签描述。

**你看到。**

- [ ] 在群里说「看看电脑里有哪些文件」，Bot 在云电脑里跑命令，工具调用卡出现，回结论，结束后出现花费卡。

**验证。**

- [ ] 运行器有单元测试覆盖消息类型转换。
- [ ] 端到端测试：起一台真实的云电脑，发一条消息，断言群里依次出现工具调用、Bot 回复、花费卡，且用量记录表多一行。
- [ ] 一条消息从发出到 Bot 第一个字出现的时间，记下来当基线。

## M4 桌面与接管

**依赖。** M3。云电脑线和控制面线。

**做什么。**

- [ ] 每个 Bot 建桌面，运行器的桌面操作工具绑定到自己的桌面。
- [ ] 桌面画面流经电脑代理到 `web`，桌面面板的四个标签：桌面、电脑终端、电脑文件、成果。
- [ ] 桌面切换下拉，列出该用户全部 Bot 的桌面和状态。
- [ ] 接管与交回。接管时暂停该 Bot 的会话，输入转给桌面，交回后会话继续。群里出现系统消息。
- [ ] 设置的电脑页：一台电脑 N 个桌面、在线状态、接管方式、登录态过期时先找你。

**你看到。**

- [ ] 原型 02 的桌面面板和 11 的桌面切换在 `web` 里能走通。接管一个正在干活的 Bot，操作，交回，Bot 从断点继续。

**验证。**

- [ ] 端到端测试：Bot 跑一个多步任务，中途接管再交回，断言任务最终完成且步数不重复。
- [ ] 画面流延迟记下来当基线。

## M5 审批

**依赖。** M3。运行器线和控制面线。

**做什么。**

- [ ] 工具的「需要点头」标记。Pi 自带工具里命令行默认不需要，MCP 工具按注解，用户可改。
- [ ] 运行器在 `tool_call` 里判断并向控制面发审批请求，等待结果。
- [ ] 控制面：审批表，审批消息推到群，侧栏角标「等你点头 N」，浏览器通知。
- [ ] `web`：审批卡的批准和拒绝按钮，回复消息也算处理。免打扰期间只记角标不推通知。

**你看到。**

- [ ] Bot 走到一个标记为付钱的工具时停下，群里出现审批卡，点拒绝后 Bot 说明放弃了这一步并继续别的。

**验证。**

- [ ] 单元测试：拒绝时工具不执行，批准时执行一次，超时不执行也不报错。
- [ ] 端到端测试覆盖批准、拒绝、回复文字三种处理方式。

## M6 工具连接与已登录站点

**依赖。** M3、M4。三条线。

**做什么。**

- [ ] 控制面：工具连接表，MCP 地址和认证信息加密存储，分配到 Bot。
- [ ] 电脑代理收到配置后，运行器按 Bot 加载 MCP 工具，只暴露分配给它的。
- [ ] 电脑代理定期列出浏览器的已登录站点和过期状态，上报控制面。
- [ ] `web`：设置的工具页，两块列表、改分配、连接新工具、接管登录。Bot 设置里的可用工具和已登录站点两行打开这一页。

**你看到。**

- [ ] 原型 07 工具页和 09 在 `web` 里能走通。连一个测试用 MCP，勾给一个 Bot，在群里让它用，工具调用卡里出现这个工具。

**验证。**

- [ ] 集成测试：没勾的 Bot 调不到这个工具。
- [ ] 端到端测试：站点过期后 Bot 停下并请求接管。

## 风险

1. 登录态共享。M1 若两个方案都不可行，退路是每个 Bot 一个浏览器各自登录，已登录站点按 Bot 列出。这会改规格的已登录站点对象。M1 结束时定。
2. Pi 的接口变化。pi-mono 更新频繁。M0 锁定版本，M1 验证的接口写进 `bot-runner` 的 README，升级时对照。
3. 客户内网部署。第一版对内用不到，但电脑代理只出站这条规则从 M3 起就要守住，否则后面改不动。
4. 单实例调度器。M9 的调度器是单实例，控制面扩到多实例前要加锁。对内够用。
5. 模型网关的计价。用量记录表存 token，金额按网关的计价表折算。计价表变了历史金额不重算。
