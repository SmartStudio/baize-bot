## 怎么读

分五期。每期结束在一个你能看到的结果上，验收就是走通 `spec/用户故事.md` 里标了这一期的故事。每个单元写做什么、你看到什么、怎么验证。单元编号是「期-序号」，比如 P1-3。

人周都是估的，没有实测，用来排人，不是承诺。三条线可以并行，控制面和 Web 一条，电脑和壳一条，运行器一条。

### 已知问题

- **每次 run 的花费是会话累计值。** `bot-runner/src/reporter.ts:84` 用 `getSessionStats().tokens` 填 `run_done`，会话续用后每次 run 重复计算。读代码确认，还没跑用例复现。P0-2 修。
- **Pi 内置的 bash、write、edit 不过审批。** P1-3 修。
- **任何设置改动都中止所有正在跑的活。** 控制面增删改 Bot、工具、skill 都调 `agents.sendConfig`，代理收到就整个换运行器。P0-3 修。
- **运行器放弃的审批，控制面还显示待批。** P0-4 修。
- **审批卡和工具行显示原始 JSON。** P0-5 修。
- **Bot 仍能 `ps eww $PPID` 读到 `AGENT_TOKEN`。** macOS 的 `ps` 读启动时的环境块。根治靠 token 不进环境，P1-2 按 N8 的 stdin 做法收掉。
- **`shared` 的 `id()` 助手所有品牌相同。** `BotId` 能赋给 `UserId`，tsc 实测通过。P0-8 修。
- **离线提示「电脑不在线，消息已留着」会让人以为回来会补派。** 实际不建 run 也不补。P0-8 改文案。
- **上游出错时 Cloudflare 的 HTML 原样进了群消息。** 网关应只留状态码。P0-8 修。

## 三、各期单元

### 第 0 期 修正确性，删企业包袱

先减后加，这一期不加新能力。

**P0-1 合入 N2。** 0.2 人周，控制面和 Web。把 `wt/n2-comm4-holes` 叠到主干，不带 `comm-turn.png`。要赶在 P1-1 之前，两边都改 `dispatch.ts` 和 `events.ts`。遗留两件一起收掉：整轮全是 `(pass)` 时仍有一条纯金额的花费行，`abandon` 断线后排队的交接留到下一回合，没有断线用例。验证是主干门禁全绿，加一条断线用例。

**P0-2 花费按 run 算。** 0.3 人周，运行器。`run_done` 报本次 run 的增量，run 开始时记下累计值，`agent_settled` 时做差。验证是运行器用例「同一个群连发两条，第二次的 token 不含第一次」，改前先看它红。

**P0-3 config 按 Bot 增量对账。** 1 人周，电脑和运行器。代理收到 config 不再整个换运行器。运行器按 Bot 对账，只重建改了的那个 Bot，正在跑的等它跑完再重建。存 skill 只落文件，不重建会话。你看到的是改一个 Bot 的描述，另一个 Bot 手上的活不停。验证是运行器用例「Bot A 在跑时改 Bot B，A 的 run 正常 run_done」「存 skill 后会话文件不变」。

**P0-4 放弃的审批标已失效。** 0.3 人周，全部三条线。运行器因停机、暂停放弃挂起的审批时发上行报文，控制面把那一行改成 `expired`，推 `approval_updated`，Web 上卡片变灰不能点。验证是控制面用例「运行器上报放弃后，点批准返回冲突，卡片状态是已失效」。

**P0-5 审批和工具参数说人话。** 0.5 人周，运行器和 Web。运行器按工具出结构化载荷，比如 bash 给命令，write 给路径和前几行，MCP 给操作名和关键参数。Web 按类型渲染，原始参数只进检查器的「高级」。验证是 Playwright 截图里审批卡和工具行没有花括号。

**P0-6 个人版账号。** 0.5 人周，控制面和 Web。删登录页的企业文案和 `users.team_name`，删系统提示里的「同事」。加注册接口，加 `POST /api/computers/local`，已登录用户用它为本机注册或重置 token，明文只在响应里出现一次。你看到的是网页上能注册，注册完直接能跟 Bot 说话。验证是控制面用例覆盖注册、重复邮箱、token 只出现一次，`git grep -n '企业\|同事\|team_name' -- packages` 没有产品文案命中。

**P0-7 删死类型。** 0.1 人周，shared。删 `shared/src/domain.ts` 里没人引用的 `Desktop`、`DesktopStatus`。验证是 typecheck 通过。

**P0-8 小修。** 0.3 人周，协调者。`id()` 助手改成泛型，按编译错误逐个修调用方。离线文案改成「电脑不在线，这条没派出去，电脑回来后再说一次」。网关出错只留状态码。验证各加一条用例。

### 第 1 期 运营最小闭环

验收是一周推广白泽的开源仓库，U1 到 U9 全部走通，你主动打开 App 不超过三次。

**P1-1 一人两台电脑。** 2 人周，shared、控制面、电脑。`computers` 按 `(owner_id, kind)` 各一行，`kind` 是 `local | remote`。hub 的连接表、宽限计时、收尾链从 owner 换成电脑。`runs` 加 `computer_id`。网关 key 按电脑轮换。派活按账号选电脑，碰某个账号的活只派到它所在的那台，没有账号约束时本机在线派本机，否则派远程。验证是控制面用例「本机和远程同时在线互不顶掉」「本机断线只收尾本机的 run」「同一台电脑的新连接仍然顶掉旧连接」「碰本机账号的活在本机离线时记失败而不是派到远程」。先在 shape 提交里改类型，让编译器指出每一处。

**P1-2 桌面 App。** 1.5 人周，电脑和壳。按 `wt/n8-electron` 的做法收成正式包。一条命令打出能装的 Mac 包，首次登录调 P0-6 的接口注册本机，token 存钥匙串，经 stdin 交给代理。菜单栏常驻，数字只数等你确认的事，下拉能直接批、能说一句。原生通知带「批准」按钮。原生标题栏，字体打包，API 地址可配。`before-quit` 的守卫看 `exitCode` 或 `signalCode`，不看 `killed`。你看到的是 U1 和 U4。验证是在一台没配过 `.env` 的 Mac 上装 App 走通 U1，`ps eww` 看代理进程环境里没有 `AGENT_TOKEN=`。

**P1-3 统一闸门。** 1.5 人周，shared、运行器、控制面。按规格第二节「确认与授权」实现判定函数，替掉 `approvalRule`。`approvals` 表加 `action` 和 `grant_id`，新增 `grants` 表。bash 命令先解析出动作类别再判。文件工具按路径判，工作目录之外走 `write_outside`。暂停和接管改成在闸门挂起，删掉 `abandon` 加 `abort()` 和排队重放。验证是运行器用例「bash 跑 curl 往外发时挂起等确认」「spend 类动作带 forever 授权仍然问」「挂起十分钟后放行，模型还能接着跑」，e2e 用例「bash 在工作目录外写文件挂起等确认」「bash 读 `~/.ssh` 被拒绝，授权了也被拒绝」「给过 `~/Downloads` 的读授权后，读那里的文件不再问」。

**P1-4 草稿和内容计划。** 1 人周，全部三条线。`publish` 类动作生成草稿，不弹「允许吗」。草稿卡就地改字。一份计划一次批完，批的是内容哈希，发出时对得上放行，对不上回到待批。你改过的地方记下来，第 2 期进品牌手册。你看到的是 U4、U6。验证是控制面用例「批过的草稿被 Bot 改过后重新待批」，Playwright 走一遍改字加批准。

**P1-5 助理浏览器和账号。** 2.5 人周，全部三条线。每台电脑一个助理专用 Chrome profile，运行器里写 CDP 浏览器工具，参照 `pi-skills/browser-tools`，不走 MCP。账号对象、四档权限、账号页。登录时把窗口弹到前台，你登完退回后台。登录过期只停碰这个账号的活，出「卡住了」通知。第一批平台是 GitHub、X、小红书。GitHub 和 X 走 OAuth，凭据在工具调用时注入，账号放远程。小红书只走浏览器，账号放本机。X 的 API 现在按什么收费、免费额度够不够每周几条，写任务书前先查，不够就也走浏览器。你看到的是 U3、U7。验证是一段录屏，Bot 在后台窗口发一条测试帖，你的鼠标没被抢。运行器用例「浏览器工具的结果里没有 cookie 和密码框内容」。

**P1-6 远程电脑。** 1 人周，电脑和控制面。在你的海外云服务器上跑控制面、电脑代理、Xvfb 和 Chrome，token 注入照 `wt/n6-overnight` 的做法。例行按执行者和账号选电脑，远程在线就不怕合盖。验证是合着 Mac 盖子，周一 09:00 的「排下周推广计划」照点在远程跑完，打开 App 时计划卡已经在「等你确认」里。

**P1-7 「今天」首页和通知。** 1.5 人周，Web 和控制面。按规格第四节做首页，用原型的方案 A「今天清单」，只做这一种排法。首页四栏、信息露出三档、右侧检查器。通知只在三种时刻发，夜里免打扰攒着。你看到的是 U4、U5、U7。验证是 Playwright 覆盖四栏和检查器，一条用例断言首页没有 runId、模型名、`T-` 编号。

**P1-8 项目页。** 1 人周，Web 和控制面。按规格第四节做六块。项目页输入框带项目 id，消息直接落进项目群。正在做的事以一行灰字出现在「等你」。成果从发布记录和计划状态来，按时间倒序。目标和指标字段第 2 期加，这一期进度条先按清单完成度画。你看到的是 U9。验证是 Playwright「在项目页连说两句，最新一轮贴着输入框，等你和成果的位置不变」。

**P1-9 一句话建项目。** 0.5 人周，全部三条线。主助理出方案卡，点「开始」建群、建卡、拉队员、建例行。机制照 `skill_offer` 先提后存。你看到的是 U2、U8。验证是控制面用例「方案卡没点开始时不建任何东西」「点两次开始只建一个项目」。

**P1-10 网关多模型。** 0.5 人周，控制面。网关按用途选模型，闸门分类走便宜的，规划走强的。收图片，浏览器截图能进模型。上游 key 必须是 ASCII 这条照旧。验证是网关用例覆盖按用途路由和带图请求。

**P1-11 上下文增量。** 0.5 人周，shared、运行器、控制面。水位住在运行器，会话里记上次看到的 `messageId`，派活时只拼之后的消息。审批和交接在上下文里带结论。验证是运行器用例「第二次 prompt 只拼上次之后的消息」「会话目录清空后第一次 prompt 用上全部 20 条」，控制面用例「审批已批准时上下文写明你批准了」。

**P1-12 按故事重写验收。** 1 人周，全部。`packages/e2e/acceptance` 改成按 U1 到 U9 在 App 里截图。然后你真用一周，数打开次数和确认次数。

### 第 2 期 小队和主动性

**P2-1 项目目标和指标。** 1.5 人周。`tasks` 加目标（数值、单位、截止）和指标。指标由例行定时读回，比如星数、粉丝、阅读量。每周一主助理排计划，每周五出复盘，复盘进「成果」。

**P2-2 品牌手册。** 1 人周。所有 Bot 共用一份，写产品事实、口吻、禁区、你的素材库。Bot 写每一条内容前先读。P1-4 记下的改动进这里。

**P2-3 主助理和建队卡。** 1 人周。Bot 加角色。注册时建主助理，项目群里它就是首席。建队卡照 `skill_offer`，只问要不要这个人。临时帮手随拉随散，不进团队页，不留记忆。你看到的是 U11。

**P2-4 Bot 页和偏好。** 1 人周。团队页点卡片进单聊，偏好记在单聊里，可看可删。「编辑」弹窗改名字、标签、描述，`Bot.tag` 改成 `tags: string[]`。你看到的是 U12、U13。

**P2-5 例行挂项目。** 0.5 人周。`routines` 加 `projectId`，`botId` 变成可换的执行者，`enabled` 换成 `on | paused | auto_paused`。连续三次没人看自己停。对话里建、预填改。你看到的是 U10。

**P2-6 分享和导入。** 0.5 人周。模板打包、默认摘要、自己挑、导入即复制。`SkillSource` 加 `template`，偏好加 `private`，插件导出不含凭据。验证是对导出包 grep 不到任何 token、cookie、对话内容。你看到的是 U14。

**P2-7 设置五页和用量。** 0.5 人周。设置收成五页，用量按月、按 Bot，月预算超了先停例行。

## 七、怎么协作

- 实现可以派给 codex、grok 或 agy 面板，任务书写 `.audit/briefs/<slug>.md`，报告回 `.audit/reports/<slug>.md`，流程在 `.claude/agents/codex-panel.md`。报告不论谁写，协调者都在工作树里重跑门禁、看过 diff 再合。
- shared 的形状改动由协调者先单独提交，各线再并行。同一期内各线不共享要改的文件。
- 各线验完先叠到一个集成分支，你亲自验过才合 main。
- `packages/web/e2e/screenshots` 的改动是测试产物，不提交。
