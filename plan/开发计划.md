# 白泽 Bot 开发计划 v0.1

日期 2026-09-18，2026-09-21 按规格待定项 2 的结论（桌面 App，Bot 住用户本机，公司一台常驻机器跑过夜的活）改过 M0、M1、M2、M4、M6、M9 和总表。依据是 spec/规格.md 和 bot-application-prototype/白泽 Bot.dc.html。这份计划是一张按顺序打勾的清单。每个里程碑结束在一个能看见的结果上，看不到结果不进下一个。时间和人手还没定，所以每个里程碑给的是粗估人周，用来帮你排人，不是承诺。

## 怎么读

一个方框是一个工作单元。每个方框写明验收它的证据，一段录屏、一条日志、一个通过的测试或一个网址。方框只在证据存在时打勾。里程碑按依赖排，M1 之前的顺序不能换，M5 之后的顺序可以按人手调。

三条工作线可以并行：控制面和客户端一条线，电脑和桌面一条线，Bot 运行器一条线。每个里程碑标了它落在哪条线上。

## 首个场景的验收剧本

这是 M11 结束时要跑通的完整剧本。前面每个里程碑各覆盖它的一段。

1. 陈默用账号密码登录，侧栏看到 5 个 Bot。
2. 点加号建群，主题任务写「Globex X3 × 200 订单」，拉小服、小销、小采，写一句话说明，建群。群顶部出现任务卡 T-2482。
3. 在群里 @小服 说「Lisa 要 200 台 X3，10 月 30 日前交，先查库存和排产」。小服在自己的桌面里打开 ERP 查数据，工具调用出现在群里，回结论和两个方案。
4. 陈默回「分两批，回复先给我看」。小服起草邮件，走到发送时群里出现审批卡「对外发送」。陈默点批准，邮件发出，群里出现「你批准了发送」。
5. 小服发交接报文给小采，报文写做了什么、没做什么、下一步。小采确认，任务卡当前经手变成小采，清单里「供货确认」变成小采的。
6. 小采查供应商门户时登录过期，停下请陈默接管。陈默在桌面面板点接管，小采松手，陈默在自己屏幕上这个浏览器里登录，点交回。小采从断点继续。全程没有画面流。
7. 小销的例行任务「每日线索早报」在早上 9 点跑在过夜机上，当时陈默的 Mac 还合着。他打开 App，结果已经在小销的群里。
8. 小服干完后问「这套流程存成 skill 吗」，陈默点存。Bot 设置的会做的活里出现「Globex 报价」。
9. 设置的用量页按 Bot 列出本周花费。

## M0 仓库、脚手架与 App 壳

**依赖。** 无。

**做什么。**

- [ ] 建 pnpm monorepo，五个包：`control-plane`、`web`、`computer-agent`、`bot-runner`、`shared`。`shared` 放规格第一部分的全部对象类型，其他包只从这里引用类型。
- [ ] `control-plane` 用 Node 加 TypeScript，HTTP 框架、PostgreSQL、迁移工具各选一个，写进仓库 README。
- [ ] `web` 用 React。把原型 `_ds` 目录里的 tokens 和 styles.css 搬进来，作为唯一的样式来源。
- [ ] CI 跑类型检查、lint、单元测试、`web` 的 Playwright 冒烟。
- [ ] 本地一条命令起全部服务，含一个 PostgreSQL。
- [ ] `web` 外面套一层 Electron 或 Tauri 的壳，壳里带上 `computer-agent`，一条命令打出一个能装的包。壳只管装界面和代理，界面代码和浏览器里跑的是同一份，开发时仍然可以只开浏览器。选 Electron 还是 Tauri 在这一步定，写进仓库 README。

**你看到。**

- [ ] 浏览器打开本地 `web`，空白主窗口用原型的字体、颜色和圆角渲染出来，侧栏和三栏布局在。
- [ ] 装上打出来的 App，同一个界面在自己的窗口里出现，退出 App 时里面的电脑代理跟着退。
- [ ] CI 在一个空提交上全绿。

**验证。**

- [ ] `shared` 里每个对象有一个类型测试，非法状态编译不过。
- [ ] Playwright 冒烟截图和原型 02 屏的空状态并排看，布局一致。

## M1 两个技术验证

**依赖。** M0。这一步的产出是结论，不是产品代码。两个验证并行，各自一人。

**验证一，Pi 嵌入。**

- [ ] 在一个 Node 进程里用 `createAgentSession` 起两个 AgentSession，各自的 cwd、会话文件、模型不同。
- [ ] 用扩展注册一个自定义工具，在 `tool_call` 事件里拦截它，等待一个外部 HTTP 请求给出批准或拒绝，拒绝时返回 block。
- [ ] 起一个最小的 OpenAI 兼容网关，把它注册成 Pi 的自定义供应商，两个会话的模型调用都经过它，网关记下每次的 token 用量。
- [ ] 把一段群消息作为提示送进会话，把流式文本和工具事件转成规格里的消息类型。

**验证一，你看到。**

- [ ] 一段录屏：两个会话同时跑，一个被拦截等批准，另一个不受影响。网关日志里两个会话的用量分开。

**验证二，本机代理与过夜机。** 原来这一条验的是 Firecracker、VNC 和登录态共享。待定项 2 定成 Bot 住用户本机之后，这三样要么不做要么自己消失，换成下面这些。

- [ ] 电脑代理在一台 Mac 上跑起来，出站连到一个测试服务，报告自己的种类是本机。
- [ ] 代理读得到这台 Mac 上浏览器的已登录站点和过期状态，用户不必再登一遍。定下读哪个浏览器、怎么读、要不要用户授权，这是本机方案最大的好处，读不到就要重新考虑。
- [ ] 让 Bot 在用户屏幕上动一次（开浏览器、点一个链接），再由用户接管：代理停掉 Bot 的输入，用户自己操作，点交回后 Bot 从断点继续。全程不经过画面流。
- [ ] 同一台 Mac 上两个 Bot 同时干活，一个碰屏幕一个不碰，确认不打架。定下抢屏幕时的排队规则。
- [ ] 在一台 Linux 机器上按两个用户各跑一个电脑代理进程，各自一份 COMPUTER_ID 和数据目录，用 Xvfb 起图形会话，互相看不见对方的文件和登录态。
- [ ] 记录这台机器的内存和 CPU 能撑几个用户同时有 Bot 在跑。
- [ ] 定规格待定项 8：Pi 自带的命令行和写文件工具在用户 Mac 上的作用范围，不能是整台机器。

**验证二，你看到。**

- [ ] 一段录屏：Bot 在用户自己的屏幕上开浏览器，用用户已有的登录态进了一个站点，中途用户接管输入再交回；与此同时另一台 Linux 机器上同一个用户的另一个 Bot 在后台跑着，屏幕上看不见它。

**收尾。**

- [ ] 把两个验证的结论写回 spec/规格.md 第五部分，关闭待定项 1、3、6、8。定不下来的写明原因。

## M3 单 Bot 派活闭环

**依赖。** M1 的结论、M2。这是关键路径上最重的一步，三条线都要动。

**做什么。**

- [ ] 控制面：群和消息表，消息的 WebSocket 推送，按用户下发本机和过夜机两份电脑配置。
- [ ] 电脑代理：正式版，出站连接、心跳、指令通道、状态上报，启动时报告自己的种类是本机还是过夜机。
- [ ] Bot 运行器：正式版，按控制面下发的 Bot 列表起 AgentSession，收群消息、回流式文本、回工具事件，运行结束回用量。
- [ ] 模型网关：正式版，供应商可配，每次调用记用量到用量记录表。
- [ ] `web`：2a 对话页，用户消息、Bot 流式消息、工具调用卡、花费卡、Bot 设置栏里的名称标签描述。

**你看到。**

- [ ] 在群里说「看看电脑里有哪些文件」，Bot 在用户自己这台 Mac 上跑命令，工具调用卡出现，回结论，结束后出现花费卡。命令的作用范围不超出待定项 8 定下的边界。

**验证。**

- [ ] 运行器有单元测试覆盖消息类型转换。
- [ ] 端到端测试：起一个真实的本机电脑代理，发一条消息，断言群里依次出现工具调用、Bot 回复、花费卡，且用量记录表多一行。
- [ ] 一条消息从发出到 Bot 第一个字出现的时间，记下来当基线。

## M4 本机桌面与接管

**依赖。** M3。电脑线和控制面线。原来这里最重的两块是 VNC 画面流和每 Bot 一台 microVM，待定项 2 定成 Bot 住本机之后两块都不做了，接管退化成电脑代理停掉 Bot 的输入，所以这个里程碑从 3 人周缩到 1。

**做什么。**

- [ ] 运行器的桌面操作工具绑定到 Bot 所在电脑的桌面。本机上是用户屏幕这一个，过夜机上是该 Bot 的 Xvfb 会话。
- [ ] 本机的抢屏幕排队：同一时刻只有一个 Bot 能动屏幕，要动之前在群里说一声，用户能拦。
- [ ] 桌面面板的四个标签：桌面、电脑终端、电脑文件、成果。本机的桌面标签显示「Bot 正在用你的屏幕」和接管按钮，不放画面。
- [ ] 桌面切换下拉，列出该用户全部 Bot 的桌面、所在电脑和状态。
- [ ] 接管与交回。接管时暂停该 Bot 的会话并停掉它的输入，用户自己操作，交回后会话从断点继续。群里出现系统消息。
- [ ] 设置的电脑页：本机和过夜机各自的在线状态、Bot 分布、接管方式、登录态过期时先找你。

**你看到。**

- [ ] 原型 02 的桌面面板和 11 的桌面切换在 App 里能走通。接管一个正在干活的 Bot，在自己屏幕上操作，交回，Bot 从断点继续。

**验证。**

- [ ] 端到端测试：Bot 跑一个多步任务，中途接管再交回，断言任务最终完成且步数不重复。
- [ ] 集成测试：一个 Bot 占着屏幕时，另一个 Bot 的屏幕操作排队而不是插队。

## M5 审批

**依赖。** M3。运行器线和控制面线。

**做什么。**

- [ ] 工具的「需要点头」标记。Pi 自带工具里命令行默认不需要，MCP 工具按注解，用户可改。
- [ ] 运行器在 `tool_call` 里判断并向控制面发审批请求，等待结果。
- [ ] 控制面：审批表，审批消息推到群，侧栏角标「等你点头 N」，浏览器通知。
- [ ] `web`：审批卡的批准和拒绝按钮，回复消息也算处理。免打扰期间只记角标不推通知。

**你看到。**

- [ ] Bot 走到一个标记为付钱的工具时停下，群里出现审批卡，点拒绝后 Bot 说明放弃了这一步并继续别的。

**验证。**

- [ ] 单元测试：拒绝时工具不执行，批准时执行一次，超时不执行也不报错。
- [ ] 端到端测试覆盖批准、拒绝、回复文字三种处理方式。

## M6 工具连接与已登录站点

**依赖。** M3。三条线。原来还依赖 M4，因为已登录站点要靠云电脑的浏览器上报；现在本机的登录态就是用户自己那个浏览器，不必等接管做完，这两个里程碑可以并行。

**做什么。**

- [ ] 控制面：工具连接表，MCP 地址和认证信息加密存储，分配到 Bot。
- [ ] 电脑代理收到配置后，运行器按 Bot 加载 MCP 工具，只暴露分配给它的。
- [ ] 电脑代理定期列出浏览器的已登录站点和过期状态，上报控制面。本机读用户自己的浏览器，过夜机读那台机器上属于该用户的浏览器，列表里标清楚来自哪台电脑。
- [ ] MCP 服务只在公司内网可达时，本机的 Bot 直接连得上。这条要有测试兜住，不能悄悄退回成走控制面转发，那等于把内网流量送出去了。
- [ ] `web`：设置的工具页，两块列表、改分配、连接新工具、接管登录。Bot 设置里的可用工具和已登录站点两行打开这一页。

**你看到。**

- [ ] 原型 07 工具页和 09 在 App 里能走通。连一个测试用 MCP，勾给一个 Bot，在群里让它用，工具调用卡里出现这个工具。用户浏览器里已经登录的站点直接出现在列表里，没有再登一遍。

**验证。**

- [ ] 集成测试：没勾的 Bot 调不到这个工具。
- [ ] 端到端测试：本机上站点过期后 Bot 停下并请求接管，过夜机上站点过期后 Bot 停下留言。

## M9 例行任务与过夜机

**依赖。** M5。

**做什么。**

- [ ] 例行任务表，触发器只做定时和 webhook。
- [ ] 控制面调度器，到点在该 Bot 的群里发起一次运行。运行记录保留 20 条。
- [ ] 失败时两种处理。试跑一次。
- [ ] 例行任务默认派到过夜机，该 Bot 在那台机器上另起一份会话和数据目录。用户能在编辑器里改成只在本机跑。
- [ ] 本机离线时例行任务照常在过夜机上跑，结果回到群里。本机重新上线后不补跑。
- [ ] `web`：2c 屏的编辑器和运行记录。

**你看到。**

- [ ] 建一个每分钟跑的例行任务，群里每分钟出现一次结果，运行记录累加。
- [ ] 退出 App，等两分钟再打开，群里有这期间过夜机跑出来的结果。

**验证。**

- [ ] 单元测试：调度器重启后不重复触发同一时刻的任务。
- [ ] 端到端测试：一次运行遇到审批时按「失败时」的设置停下。

## M10 skill

**依赖。** M3。

**做什么。**

- [ ] 运行器在多步任务结束后问用户存不存，存时写 skill 文件到该 Bot 的目录，电脑代理同步到控制面。
- [ ] 控制面：skill 表，改步骤、删除、复制给别的 Bot。复制时电脑代理把文件放到目标 Bot 的目录。
- [ ] 对话里 / 引用。

## 风险

1. 读不到本机浏览器的登录态。Bot 住本机的好处大半压在这一条上。M1 若发现读不到或要用户每次授权，退路是 Bot 自己开一个受控的浏览器实例，用户在里面登一次，登录态按电脑存。这会让「用你平时登好的那个浏览器」这句承诺缩水。M1 结束时定。
2. Bot 在用户自己的机器上能碰什么。云电脑时代 Bot 弄坏的是一台随时能重建的虚拟机，现在弄坏的是同事的 Mac。命令行和写文件的作用范围必须在 M1 之前定死，并且从 M3 起就守住，规格待定项 8 记着这件事。
3. 本机抢屏幕。同一时刻只有一个 Bot 能动屏幕，用户自己也在用这台机器。排队规则做得不好，表现就是 Bot 半夜不动、白天乱点。M1 验，M4 做。
4. Pi 的接口变化。pi-mono 更新频繁。M0 锁定版本，M1 验证的接口写进 `bot-runner` 的 README，升级时对照。
5. 客户内网部署。第一版对内用不到，但电脑代理只出站这条规则从 M3 起就要守住，否则后面改不动。Bot 住本机之后这条更容易守，本机本来就在内网里。
6. 单实例调度器。M9 的调度器是单实例，控制面扩到多实例前要加锁。对内够用。
7. 模型网关的计价。用量记录表存 token，金额按网关的计价表折算。计价表变了历史金额不重算。
